# Task 013 handoff

Backlog task 13: Discard file, hunk or lines, undoable. This is the **core half** only. Branch `task-013-discard`, from `origin/main` at `8126f88`. `docs/PLAN.md` row 13 is now "Core done".

## What changed

- **Patch building (pure, `diff`).** `Direction::Discard` (diff is index to worktree). The rewrite is the one of `Unstage` (the patch applies to the diff's new side, here the worktree text, and turns each selected line back into the index's), so there is no second table: `Direction::reverts()` names the two. A discard of an untracked file is a deleted-file patch, a discard of a deleted file is a new-file patch (mode from the index). The widening at an unterminated last line applies to discards too.
- **Core.**
  - `Event::DiscardRequested(DiscardRequest { selection, patch, based_on, expect_file })`, `WriteRequest::Discard`, `Action::Discard`, `Command::ApplyPatchToWorktree { op, patch, path, expect_index, expect_file }` (a write for the lock rules).
  - A discard waits for a fresh snapshot and a free lock like any write, and is refused with `Refusal::RepoBusy` during a merge, rebase, cherry-pick or revert, `Refusal::StaleDiff` when `based_on` is not the index on disk, and `Refusal::NothingSelected` for an empty patch. It emits `SnapshotForUndo` (label such as "Discard 3 lines in a.rs"; no refs, `IndexEffect::Untouched`, `Reversal::Discard { path }`) then `ApplyPatchToWorktree`. A running discard is not cancelled (like a stash). A failed one leaves no point and prunes its saved blobs.
  - Undo: `plan()` turns a discard entry into an `UndoReplay` whose `discard: Some(DiscardRestore { discarded, path })` carries no refs and no index work. It is refused only in a merge/rebase phase (`RepoBusy`); refs, `HEAD` and index do not matter to it, the shell compares the file's bytes.
- **Shell.** New `crates/shell/src/discard.rs`:
  - `DiscardRunner::apply`: refuses on `index.lock`, a different index id, a worktree file whose exact bytes (git blob id, no filters) differ from `expect_file`, or a saved copy that differs from `expect_file`; then `git apply --whitespace=nowarn --check -` and the same without `--check`, patch on stdin, no `--index` (the index file is never touched; tested byte for byte); then records the result.
  - Saved content: `UndoRunner::snapshot` now also stores the file as a blob (`git hash-object -w --no-filters --stdin`), builds a one-entry tree with its mode through a private index file (`update-index --cacheinfo`, `write-tree`) and keeps it as `refs/invoke-git/undo/<op>-discard`. After a successful discard the file as it was left is saved as `<op>-discard-after`. An empty tree means "the file does not exist". `prune` deletes both refs.
  - Undo (`UndoRunner::restore_discard`): reads both trees, refuses with `PreconditionChanged` unless the file still hashes to the `-discard-after` entry ("was changed after the discard; undo does not overwrite it"), then writes the saved blob back (temp file, rename, executable bit from the saved mode on Unix) or removes the file and the folders it leaves empty. All checks come before the first write.
  - Paths are validated (`worktree_path`): only plain relative components, nothing under `.git`; a discard (and its undo) writes and deletes files.
  - `load_inputs` returns `DiffInputs::new_blob`, the blob id of the new side's bytes (hashed with gix for the worktree), which the UI sends as `expect_file`. `staging::blob_id` is public.
- **Harness.** `Transition::Discard` (random pick, in the write mix, also while `index.lock` is held) and `DiscardThenUndo` (discard, maybe edit the same file, undo). The model checks law 7 inline ("law 7:": no other file changes, a refused or failed discard changes nothing) and models the undo: it must give the exact bytes back, and must fail with `PreconditionChanged` when the file was edited since. Bookkeeping knows the two extra refs. `crates/harness/src/laws.rs`: law 7 is now owned by `law_7_discard_changes_only_selected_lines` (shell), with the pure tests, the harness and the marker as support; `pending_laws_are_the_ones_whose_tasks_are_not_merged` now asserts no law is pending.
- **Tests.**
  - `crates/diff/tests/patch.rs` (+4, 3 extended to three directions): exact selected change for discards, discard-all = index text, a discarded hunk keeps the other hunks, untracked/deleted file headers, missing final newline restored.
  - `crates/core/tests/discard_props.rs` (13): dispatch commands, labels, stale index (at request and at dispatch), empty patch, all four busy phases, lock wait, undo plan touches only the file (and ignores `HEAD` and index), undo refused in a merge, failed discard leaves no point, no cancel, proptest "a discard runs iff its diff matches the index and the repo is clean".
  - `crates/shell/tests/discard.rs` (21): `law_7_discard_changes_only_selected_lines` (40 random files and selections on real repos with CRLF, no final newline, unicode and spaced paths; compares the worktree file with an independent oracle, every other file byte for byte, HEAD/index entries/branches, the index file byte for byte, then undo restores everything); CRLF hunk and line discards; missing final newline both ways; unicode path; untracked (including empty) and deleted files and their undo; modes (Unix); binary files refused by `load_inputs` with a reason and a text patch aimed at one changes nothing; stale index; file edited after the diff; patch that does not fit; paths outside the repo; merge in progress; undo refuses over a later edit and then works once the file is back; chained undo; content survives `git gc`; the runner's two file checks by hand; folder emptied by undo.

## What is unfinished

Wiring: `Command::ApplyPatchToWorktree` -> `DiscardRunner::apply`; the snapshot and replay commands are the ones of task 12 (`UndoRunner`). - Not covered by a text patch: binary files, non-UTF-8 text, symlinks, submodules and mode-only changes are refused with a reason by `load_inputs` (`NotText`). Discarding a tracked binary file would need `git checkout -- <path>` with its content saved as a blob; discarding an untracked binary file needs the same save and a plain delete. The save/restore here is byte-exact, so only the apply step is missing; no `GitArgs` variant exists for it.
- One request is one file. "Discard all changes" in the UI is a loop of requests (one undo point each) unless the spec wants one point for all.
- Undo points are in memory only (task 12's open SQLite question). A restart leaves `refs/invoke-git/undo/*` refs behind that nothing prunes.

## Spec questions, with proposed answers

1. **The worktree file is part of "what the write expects".** The spec says the shell checks "the index (or worktree file) still matches" the blob id the patch was built from. The index id alone cannot say that for a discard (a discard leaves it unchanged, and the user may be typing), so the request carries `expect_file` (git blob id of the worktree bytes, `None` when absent) and the shell refuses on any difference, before and after the snapshot. Proposed: record `expect_file` in `core-design.md` and `diff-engine.md` ("Safety").
2. **Discard is `Unstage` on the worktree text.** The table in `diff-engine.md` has the same rewrite for both; the code names it `Direction::Discard` and shares the rules. Proposed: say so in the table.
3. **Where the discarded content lives.** Spec: "blobs plus file paths and modes". Implemented as one tree per discard (`<op>-discard`, entry = path, mode and blob), plus a second tree for the result (`<op>-discard-after`) that an undo compares before writing. Proposed: add the second tree to "Undo design", and the rule that an undo never overwrites a file changed since.
4. **Undo of a discard checks the file, not refs or index.** The generic undo checks head, refs and index; a discard touches none of them, so none applies. Refused only in a merge/rebase phase (the same `RepoBusy` as other undos). A branch switch that did not change the file does not block it. Proposed: add to "Replaying an undo".
5. **Permissions.** `git apply` creates and rewrites files with `0777` minus the umask for executable files (git's own rule), so an executable file may end up `0775` instead of `0755` after a discard. The undo writes exactly `0755`/`0644`. Only the executable bit is a promise. Proposed: accept.
6. **Filters.** `core.autocrlf` and clean filters (task 11 question 4): the worktree file is hashed and saved raw, and `git apply` converts through the user's config. With `core.autocrlf=true` the patch built from the raw worktree text may not fit (refused, nothing changes). Same fix as task 11: run the worktree text through the filters in `load_inputs`. Test fixtures isolate config, so this is not exercised.
7. **Cancel.** A running discard ignores `OpCancelRequested` (like stashes), since killing it between the apply and the after-record would lose the undo. It is local and quick.
8. **Undo ordering.** Entries below the top are untouched: undoing a discard that is not the newest needs the newer ones undone first (LIFO), as for every undo.

## Anything surprising

- The replay's `op` is the undo's own id, not the discard's, so the restore needs the id of the discard (`DiscardRestore::discarded`). The first version used the undo's id and found no saved copy; the shell tests caught it at once.
- Real git refused most hostile paths on its own (`update-index --cacheinfo` rejects `..` and `.git/...`), which hid a dropped path check. The shell's own check is defence in depth and now has a test that needs its message.
- With the first mutation run, three checks were masked by their neighbours (S1/S2, S7, S9). The runner-level test calls `UndoRunner::snapshot` and `DiscardRunner::apply` by hand to separate them.
- The harness needed a composite step: a plain random walk almost never writes the same file between a discard and its undo, so `DiscardThenUndo` forces the sequence.

- **The question first (`app::discard`).** A warning bar names what will change and that it can be undone, and its danger button names the action: `Discard file` ("every unstaged change in a.rs: 2 lines added, 1 line removed"), `Delete file` (untracked: "Git does not track it yet"), `Restore file` (a file you deleted), `Discard hunk`, `Discard 3 lines`, `Discard 5 files`. Nothing is written before the button is pressed; `Cancel` or choosing another file drops the question.
- **The request is built when you click**, from the diff on screen, and carries `based_on` and `expect_file` (`InputsMeta::new_blob`). If the index or the file changed before the yes, the core refuses it and the bar says so (the usual stale-diff refusal).
- **Discard all** asks once and then goes file by file through the same queue as bulk staging (`diff_load::Verb::Discard`), each file read fresh; every file has its own undo point (Undo reverses the last file first).
- **core.autocrlf** (the question left open in this task and in task 11): `a_discard_under_autocrlf_keeps_the_crlf_worktree` in `crates/shell/tests/discard.rs` runs a hunk discard, its undo and a whole-file discard through the real runners on a repo with `core.autocrlf=true` (index LF, worktree CRLF; the test asserts that setup with `git ls-files --eol`). It passes, and fails when `load_inputs` stops filtering the worktree text. So the answer to question 6 above: no change was needed in the discard runner; the filter added in task 11 is enough.

### Windows checklist (tasks 2, 7, 10, 11, 14, 15, 18, 19 apply too)

Use a throwaway repo with a few modified files, an untracked file and a deleted file. Run `cargo run --release -p app -- C:\path\to\repo`.

1. Open a modified file in the Changes page: the hunk rows show `Stage hunk` and `Discard hunk` (red); the toolbar shows `Discard file`. A staged file shows none of the discard buttons.
2. `Discard hunk`: a yellow bar says what goes (counts), nothing changed on disk yet; `Cancel` closes it. Press it again and confirm: only that hunk is gone (check with `git diff`), the other hunks remain, and the header shows `Undo  Discard hunk 2 in <file>`. Undo restores the exact bytes.
3. Tick two changed lines, press `Discard 2 lines`: only those lines revert.
4. On a **CRLF** file (and with `git config core.autocrlf true`): discard a hunk and a line, then Undo; the file keeps its CRLF line endings and nothing else changes (`git diff` and a hex view).
5. `Discard file` on an untracked file: the bar says `This deletes <file>. Git does not track it yet.`; the button is `Delete file`; confirm: the file is gone; Undo brings it back byte for byte. On a file you deleted: `Restore file`.
6. `Discard all` in the unstaged section: one bar with the number of files; confirm: all go; press Undo once per file to bring them all back (untracked ones included).
7. Change the file in another editor while the bar is open, then confirm: the discard is refused (a notice) and your editor change is kept.
8. Select another file while the bar is open: the bar goes away.
9. A binary file in the list: `Discard file` on it leaves a message that no text diff exists, and nothing is deleted.
10. At 150% and 200% scale the bar and the hunk-row buttons are not clipped.
