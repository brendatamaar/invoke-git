# Task 014

## Goal

The core (non-GPUI) half of commit, amend and the commit message editor:

- pure message logic: cleanup (LF only, whitespace), subject and body split, subject length hint as data (soft at 50, firm at 72, never a refusal), empty and whitespace-only refusal with a stated reason, the undo label of a commit
- core decisions on the fresh snapshot: refuse a plain commit with nothing staged, amend of an unborn branch, amend during a merge, a merge with conflicts, and any commit during a rebase, cherry-pick or revert; allow a plain commit during a resolved merge as "conclude merge"
- shell: hook failures (pre-commit, prepare-commit-msg, commit-msg, pre-merge-commit) as their own class with the hook's output; a missing identity as an `Environment` failure with a clear message; the previous message (amend) and git's merge message (conclude merge) as editor starting text, read through gix
- amend and commit undo exactly (law 8), and only the current branch moves (law 9)

## PRD law numbers

- 8: undo after commit and amend restores every ref and the index exactly (owning test stays in `crates/shell/tests/undo.rs`; amend is already an action of the model-based harness)
- 9: a commit or an amend moves only the current branch
- 12: a commit waits for `index.lock` (owning test stays in the harness)
- Also rule 5 (the write carries the head and index it expects) and `docs/spec/core-design.md` "Errors" (nothing to commit and an empty message are expected outcomes, not errors).

## Constraints

- `core` stays pure; the message logic is plain text functions.
- Writes go through the system git CLI; the previous message is a read through gix.
- No new dependencies. The hook name is found in git's trace2 event stream, parsed by hand (no JSON crate).
- Sign-off is out of scope. No UI changes.

## Acceptance criteria

- Pure proptests: cleanup is idempotent, keeps every non-whitespace character, never leaves a `\r`, and treats CRLF and LF alike; parse refuses exactly the messages with nothing in them; subject and body split a message without losing text; the hint changes level exactly past 50 and 72 `char`s; the label never splits a `char`.
- Core tests: every commit request is run (with the cleaned message) or refused with a stated reason, in agreement with an independent statement of the rules over head, phase, staged state and amend.
- Integration tests on temp repos: commit with a body, CRLF input, `#` lines, unicode / long / multi-line labels, empty commit and empty message refused, amend (author kept, staged changes included, undo exact, no other ref moves), amend of an unborn branch, first commit and its undo, hook rejection (pre-commit, commit-msg, a hook that prints "nothing to commit", a failing post-commit that is not a failure), missing identity, conclude merge (conflicted refused, resolved allowed, nothing staged allowed, amend refused, undo stops with a reason), lock wait.
- Each new test is shown to fail once by planting a bug (listed in the DONE file).
- `cargo xtask check` passes.

## Out of scope

- The message editor widget, IME, the subject-length rendering, the amend checkbox (the UI half of task 14).
- Sign-off, GPG or SSH signing, `--reset-author`, `--date`.
- Continuing a rebase, cherry-pick or revert (task 23).
- Restoring `MERGE_HEAD` on undo of a merge commit.
