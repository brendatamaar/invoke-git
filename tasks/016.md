# Task 016

## Goal

The core (non-GPUI) half of clone with progress, cancel and the in-app auth prompt:

- a small pure state machine for clone jobs (`invoke_core::clone`), because no repo exists yet to hold the op in `RepoState`; same op lifecycle (running with progress, awaiting auth, cancelling, ended)
- `crates/askpass`: the `GIT_ASKPASS` / `SSH_ASKPASS` helper binary (std only) and the wire protocol it shares with the shell
- shell: `CloneRunner` running `git clone --progress` through the existing child-process machinery, an askpass server (named pipe on Windows, Unix socket elsewhere) that turns prompts into `AuthNeeded` and answers into the helper's stdout, and cleanup so a failed or cancelled clone leaves no half-written folder

16 in [the plan](../docs/PLAN.md#v01-backlog): "Clone with progress, cancel and in-app auth prompt (`GIT_ASKPASS`)". This is the core half; the clone dialog (UI) waits for the Phase 0 gate.

## PRD law numbers

- 13: cancel kills the whole tree (job object or process group) and reports `Cancelled`; every outcome is one finished event; a cancelled clone leaves nothing on disk.
- Auth and forge integration: the app registers itself as `GIT_ASKPASS` / `SSH_ASKPASS`; no passwords or keys are stored; nothing is written to disk.

## Constraints

- `core` stays pure: the clone machine does no IO. All IO is in `shell`.
- Reuse the runner's spawn, drain, progress and cancel code; do not duplicate it.
- `askpass` is std only. `windows-sys` (approved) is used by the shell's pipe server only.
- `AuthAnswer` stays redacted in debug output; secrets are never logged or written to disk.
- Delete the target folder only if the clone created it.
- Tests use temp folders, local bare repos (file:// URLs) and a throwaway server on 127.0.0.1; no real hosts.

## Acceptance criteria

- `cargo test -p invoke-core -p askpass -p shell` passes on Linux:
  - clone from a local bare repo succeeds with progress events
  - cancel mid-clone (slow `uploadpack.packObjectsHook`) reports `Cancelled`, removes the target and the leading folders it created, and kills the hook's grandchild
  - an existing empty target is kept (emptied) after a failure; a non-empty target is refused untouched
  - the helper binary round trip: prompt goes to the server, the answer comes out of stdout, cancel and a wrong token exit non-zero with empty stdout
  - a clone against a local HTTP server that always answers 401 prompts for username and password in-app and ends as `Failed(Auth)`
  - property tests for the clone lifecycle and the wire protocol
- Each new test is shown to fail once against a planted bug.
- `cargo check` and `cargo clippy` pass for `--target x86_64-pc-windows-msvc` on `shell`, `askpass` and `invoke-core`.
- `cargo xtask check` passes.

## UI half (branch `task-016-clone-ui`)

The clone dialog and the in-app credential prompt. Files: `crates/app/src/{clone_view,auth_prompt,workspace,notice}.rs`, `crates/ui/src/{text_editor,welcome}.rs`. It runs the core's `step_clone` and the shell's `CloneRunner`; no new dependencies.

- The welcome screen gets `Clone repository…`; the dialog asks for the address, the folder to clone into (default: `Documents` of the home folder) and the folder name (default: from the address), then shows progress with Cancel, asks for credentials in the app, and opens the new repo in a tab.
- Failure and cancel are shown in the dialog and leave nothing on disk.
- Acceptance: unit tests for the folder name, the phase-to-screen mapping and the prompt wording; the masked field; a run in the real app against a local source and against a server that demands credentials; `cargo xtask check`; a Windows checklist in `016.DONE.md`.
