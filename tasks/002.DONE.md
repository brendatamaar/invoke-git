# Task 002 handoff

Backlog task 2: Design tokens crate and component layer skeleton over GPUI. Only the `tokens` crate is done ("Core done"). Branch `task-002-tokens`, from `origin/main`.

## What changed

- **New crate `crates/tokens`** (package and library `tokens`). No runtime dependencies, no GPUI. `proptest` is a dev-dependency only.
  - `build.rs` reads `docs/design/tokens.json` on every build and writes `$OUT_DIR/generated.rs`. A malformed token (bad hex, bad `px`, missing theme key, dangling or cyclic alias) fails the build with the token's name.
  - `src/lib.rs` holds the plain types: `Rgba { r, g, b: u8, a: f32 }` (with `to_u32` and WCAG `contrast_ratio`), `Theme` (`Dark` default, `Light`), `Palette`, `Shadow`/`ShadowLayer`, `FontFamily`, `TextStyle`.
  - Generated: `DARK` and `LIGHT` palettes (one field per colour token, plus `shadow_overlay`), `Palette::COLOR_NAMES`, `Palette::colors()`, `SPACE_*`, `RADIUS_*`, size consts (`ROW_LIST`, `ROW_DIFF`, `LANE`, ...) as `f32` logical px, the `SPACINGS`/`RADII`/`SIZES` lists, `SANS_STACK`/`MONO_STACK`, `TEXT_*` styles and `TEXT_STYLES`. `Palette::lane(i)` rotates through `lane_1` to `lane_8`. The `focus` alias resolves to `accent` at build time.
  - `support/json.rs` is a small std-only JSON reader, shared by `build.rs` and the tests through `#[path]`.
- **Tests** (`crates/tokens/tests/tokens.rs`, 24 tests, plus 3 unit tests):
  - Every colour in the JSON equals the Rust value in both themes (decoded independently of `build.rs`), and Rust has no extra colour. Spacing, radius, size, type styles, font stacks and shadows match too.
  - Light and dark have the same keys, themes are `[dark, light]`, dark is the default, `focus` equals `accent`.
  - README rules: `ink` and `ink-muted` at 4.5:1 on every `bg-*` and `ink-faint` on `bg-panel`; `line-control` 3:1 on `bg-app` and `bg-panel`; `ink` 4.5:1 on all four diff backgrounds; add and remove inks 4.5:1 on their lines and on the panel, and 1.2:1 apart; accent, danger and warning text pairs 4.5:1; lanes 3:1 on `bg-panel` and distinct; 4px spacing grid, increasing; radii increasing; no font under 11px and 11px only for `label`; `code` line height equals `row-diff`.
  - Reader: proptest round trip, no panic on garbage, truncated documents are errors, every escape decoded, malformed input rejected.
- `docs/PLAN.md` row 2 is now "Core done". `cargo xtask check` passes (core only on this VPS).

**Why `build.rs` and not a committed `generated.rs` with `cargo xtask tokens`:** the build always reads the JSON, so the Rust cannot be out of date and there is no extra command or freshness test to forget. The cost is a small hand-written JSON reader (about 200 lines), which would be needed either way because `serde` is not in the build-vs-library table.

## What is unfinished

- The GPUI component layer skeleton (rest of task 2) waits for the Phase 0 gate. It should convert `Rgba` and `Theme` to GPUI colours and load Inter and JetBrains Mono.
- Motion is not a token family yet (README), so there are no motion consts.

**Spec questions (proposed answers):**

1. **`ink-faint` scope.** The README says "Every text token meets 4.5:1 on every `bg-*` token ... and `ink-faint` still does on `bg-panel`". That reads as if `ink-faint` is exempt from the other surfaces. **Proposed:** keep it as tested (`ink` and `ink-muted` on all four surfaces, `ink-faint` on `bg-panel` only) and word the README sentence plainly.
2. **"3:1 on both panels" for `line-control`.** I tested `bg-app` and `bg-panel`. **Proposed:** name the two surfaces in the README.
3. **"Differ in lightness".** The README gives no number for add-ink versus remove-ink. I chose a 1.2:1 contrast between them (light pair is 1.26). **Proposed:** record that number in the README, or tighten the light-theme colours.
4. **Sizes.** The README speaks of `space-1` to `space-8`, but the scale has no `space-5` or `space-7`. Tests assert the 4px grid and order, not a fixed list. No action needed unless a gap is a mistake.

## Anything surprising

- Every contrast rule in the README already holds in `tokens.json`; no colour needed changing.
- `clippy::assertions_on_constants` rejects `assert!` on two consts, so the radii test compares the generated list instead.
