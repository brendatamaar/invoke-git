# Task P0-3

## Goal

Build Prototype B in `spike-graph`: a virtualized commit graph of the Linux kernel clone with custom-drawn lanes, scrollable from the newest commit to 100k deep, with readouts so P0-4 can measure it against the Phase 0 gate.

## Backlog task number

P0-3, the third of four Phase 0 tasks (P0-1 to P0-4). It covers "Prototype B — commit graph" in [the plan](../docs/PLAN.md#phase-0--gpui-spike). It is not a v0.1 backlog row.

## Files likely touched

- `crates/spike-graph/` (all of it)
- `Cargo.toml`, `Cargo.lock`
- `docs/spike-results.md` (notes only; measurement is P0-4)
- `tasks/P0-3.DONE.md`

## PRD law numbers

None directly. The lane layout follows the spec that law 14 will test, and its tests check the same properties informally.

## Constraints

- Based on `p0-2-diff-view` (P0-1 and P0-2 are not merged yet).
- `gix` for reads (in the PRD's library table). No other new dependencies.
- Read the kernel clone at `C:\dev\fixtures\linux` only; never write to it.
- Follow [the commit graph spec](../docs/spec/commit-graph.md): topological order from HEAD (the plan says HEAD only for the spike), pages of 5,000, naive lane assignment, 28 px rows, 14 px lanes capped at 16 with a "+N" marker, lane colours `lane-1` to `lane-8`, HEAD as an `accent` ring, merges hollow, and metadata read lazily for visible rows.
- Release builds only for running. The agent cannot see the window; the user verifies anything visual.

## Steps

1. Walk commits with gix in topological order from HEAD on a background thread, using the commit-graph file, and lay them out in pages of 5,000 that continue each other's lane state.
2. Render rows in a `uniform_list` with columns for graph, subject, author, date and short hash; draw lanes, curves and dots with a custom GPUI element (`canvas`).
3. Read subject, author and date only for visible rows plus a buffer, cached per row.
4. Scroll with the mouse wheel and a custom scrollbar dragged end to end.
5. Readouts as in Prototype A (fps, frame interval, build time, blank rows, first paint from the first page ready), plus `--sweep N` scrolling 100k deep for repeatable runs.

## Acceptance criteria

- `cargo build --release -p spike-graph` succeeds.
- `cargo run --release -p spike-graph` shows the kernel graph with lanes and metadata and scrolls 100k commits deep (the user verifies).
- `spike-graph --sweep 20` completes with 0 blank rows.
- `cargo xtask check` passes.

## Out of scope

- Starting points other than HEAD, ref labels, lane hover, selection, refresh on ref change, the missing-commit-graph banner, shallow-clone stubs.
- The gate measurement (P0-4).
