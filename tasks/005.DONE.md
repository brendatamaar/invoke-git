## What changed

Branch `task-005-repo-state`, from `origin/main` at `52ab51a`.

- **`crates/core/src/detect.rs` (pure).**
  - `Markers` describes which in-progress markers exist (`rebase-merge/`, `rebase-apply/` with the raw text of their counter files, `MERGE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`).
  - `parse_counter` reads a decimal counter with optional surrounding whitespace.
  - `detect_phase(&Markers, Conflicts) -> Phase` applies the spec's ordered rules. 6 tests (proptest and one unit).
- **`crates/shell/src/discover.rs`.** `discover(start) -> Discovered { paths: RepoPaths, common_dir }`, built on `gix::discover`. It works from the worktree root, any subfolder or the git dir, follows `.git` files (linked worktrees, `--separate-git-dir`), and returns `DiscoverError::Bare` or `NotARepo` with readable messages. `paths.git_dir` is the worktree's own git dir; `common_dir` is the shared one.
- **`crates/shell/src/read.rs`.** `read_state(&RepoPaths) -> Result<DiskState, Failure>` reads head, phase, index id, conflicts, refs and lock, with gix and plain file reads only. `read_event` and `execute(paths, &Command)` turn `Command::ReadState` into `Event::StateRead` or `Event::ReadFailed`, and give `None` for any other command. The scope is ignored: every read is a whole `DiskState`.
  - Conflicts: unique paths with an index entry at stage 1-3, sorted (gix `open_index`).
  - Refs: everything under `refs/`, loose and packed, with the id each names (an annotated tag names its tag object). A symbolic ref such as `refs/remotes/origin/HEAD` gives its target's id; a dangling one is left out.
  - Markers are read from the worktree's own git dir, never the common dir.
- **`crates/shell/src/precondition.rs`.** `current()` is split into `open`, `read_head` and `index_id`, so `read_state` and the write check share them. `index_id` now handles `index.skipHash` (Q4 of task 4): with an all-zero trailer the id is built from file size, mtime seconds and nanos, zero-padded to the hash width. `RepoPaths` derives `PartialEq, Eq`.
- **`crates/shell/Cargo.toml`.** gix gets the `index` feature (part of gix itself, no new top-level dependency; it pulls `gix-index` into `Cargo.lock`).
- `StatusSnapshot` is left empty (task 11). Row 5 in `docs/PLAN.md` is Done.
- **Tests.** Core: 6 new unit and property tests (8 in the crate). Shell: 18 integration tests in `crates/shell/tests/read_state.rs`, on generated temp repos with system and global config shut out. They cover clean, unborn, detached, a merge with real conflicts (and after resolving), a stopped rebase (merge backend: step 2 of 3; apply backend: next 2 of last 3), cherry-pick and revert with conflicts, held `index.lock`, packed plus loose refs, a clone with `origin/HEAD`, discovery from root, subfolder and git dir, bare and plain-folder refusal, `.git` as a file, a linked worktree (own markers, shared refs, separate index id), `index.skipHash`, and the `ReadState` glue (including `ReadFailed` and non-read commands). `git for-each-ref` and `git ls-files -u` are the oracles for refs and conflicts.

### Spec questions (proposed answers)

1. **`git am` looks like a rebase.** `rebase-apply/` is also used by `git am`, which the spec's rule 1 reports as `Rebasing`. **Proposed:** treat `rebase-apply/` containing an `applying` file as not a rebase and add a phase for it when someone needs it (v0.1 does not).
2. **Both rebase directories at once.** Not a state git produces. `rebase-merge` wins here. **Proposed:** keep.
3. **Counters missing or unparseable.** Git makes the rebase directory a moment before it writes `msgnum` and `end`, so a read in that window sees a rebase with no counters. They read as 0 and 0; the next read (the watcher fires on the marker files) corrects it. **Proposed:** keep, or make `Rebasing { step, total }` optional if the UI should show "starting".
4. **Lock ownership.** Any `index.lock` is `HeldByOther`. `HeldByUs` needs the shell to know which of its own ops hold the lock, which the runner can answer when task 7 wires things together. **Proposed:** the runner tracks "a git child of ours is running" and the read glue reports `HeldByUs` when `index.lock` exists and one is; otherwise `HeldByOther`.
5. **Read failures are `Bug`.** `ErrorClass` has no class for "path is not a repo any more" (folder deleted or moved). **Proposed:** in task 7, map a missing git dir to `Environment` ("repo not found") and keep `Bug` for unexpected content.
6. **skipHash ids are weaker.** With `index.skipHash=true` the id is size plus mtime, so two changes within one mtime tick that leave the size equal look the same. A git CLI write checks the real index, so the damage is limited to the check being less strict. **Proposed:** accept; skipHash is opt-in and rare.
7. **Discovery uses gix's default open options**, so it follows the user's config for trust (`safe.directory`). A repo owned by someone else gets an error from gix, shown in `NotARepo`'s reason.

## Anything surprising

- **Worktrees sharing one cargo target dir clobber each other.** Cargo hashes path crates by workspace-relative path, so `invoke-core` built in two worktrees got the same artifact name in `/home/brendatama/invoke-git/target`. This broke my build (`could not find detect in invoke_core`) and made an early mutation run unreliable. I used my own `CARGO_TARGET_DIR` for the rest of the task (240 MB with `CARGO_PROFILE_DEV_DEBUG=0`). **Proposed:** give each parallel agent its own target dir, or build with distinct `-C metadata`. The shared scratchpad script `cg.sh` was also overwritten by another agent, so I used my own.
- **My mutation script restored files with an old mtime**, so cargo did not rebuild them and later mutations ran against stale code. After fixing it (touch on restore) the full mutation run was redone, and the table above is from that run. Worth knowing for the earlier tasks' mutation loops.
- **A planted bug was missed at first:** the skipHash id with size zeroed still changed with mtime, so the repo-level test passed. A unit-style test that fixes the mtime with `File::set_modified` and varies size, mtime and trailer separately now catches both.
- The "wrong `MERGE_HEAD` name" mutant (`MERGE_MSG`) is not caught by the plain merge tests, because git leaves a `MERGE_MSG` during a merge as well. The other tests catch it.
- **Windows CI caught a fixture bug.** `GIT_CONFIG_GLOBAL` pointing at a `\\?\` path (from `fs::canonicalize`) makes Git for Windows fail with "unknown error occurred while reading the configuration files". The sandbox now uses the plain temp path, and the discovery assertions compare canonicalized forms of both sides.
- gix opens a linked worktree's git dir (`.git/worktrees/x`) directly, finds the common dir by itself, and returns its HEAD, index and the shared refs correctly.
