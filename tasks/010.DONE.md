# Task 010 handoff

Backlog task 10: Diff viewer, split and unified, virtualized. Branch `task-010-diff-viewer` (stacked on `task-011-autocrlf`; nothing is merged to `main` until the end of Phase 1).

## What changed

- **`ui` crate: the viewer.**
  - `diff_rows.rs` (pure): a `TextDiff` as rows. Unified is one row per line. Split puts context on both sides and each run of removed lines beside the run of added lines that replaced it, paired by position, the shorter side padded with a blank cell. `hunk_header` writes `@@ -a,b +c,d @@`.
  - `code_text.rs` (pure): tabs become four spaces (with the byte offsets of the colour and word-change ranges moved along), and `merge_styles` merges the syntax colours with the word-level changes into non-overlapping runs.
  - `diff_view.rs`: `DiffView`, an entity that renders a `Content` (`Loading`, `Message`, or `Text(DiffData)`). Toolbar with the file, `+n −m`, a context switch (3 lines, 10 lines, whole file) and Split or Unified. A `uniform_list` of `row-diff` rows, line numbers on both sides, signs, add and remove backgrounds, `add-bg-strong` and `remove-bg-strong` behind word-level changes, syntax colours, and a faint `\ No newline at end of file` after a last line without a newline. Word-level marks are computed only for the hunks that scroll into view. `compute` (the diff) and `highlight_sides` (both sides parsed at the same time) are the two CPU steps the caller runs off the UI thread; `set_spans` adds the colours when the parse is done; `replace_content` refreshes without losing the scroll position.
  - `scrollbar.rs`: the Phase 0 scrollbar made reusable, with its geometry in pure functions. It also serves the file list.
  - `changes.rs`: the flat list of changed files (unstaged first, then staged, as in the design), virtualized, with the git status letter in colour.
  - `components/segmented.rs`: the segmented control. `text.rs`: code text styles turn **font ligatures off** (JetBrains Mono otherwise joins `->` into an arrow, which a diff must not do). `summary.rs`: `RepoSummary` is now the header (branch pill, tracking, path) and banners; the body moved to the list and the viewer.
  - `examples/diff.rs`: the viewer on sample text, or `--fixture` for the 50k-line files.
- **`app` crate.** `RepoView` is what a repo tab shows: header, file list, diff. It reads the two sides on a background thread (`diff_load.rs`: `shell::load_inputs`, with up to three tries when the index moves), shows the diff, then the colours when the parse ends. It opens the first changed file on its own, reloads the open diff after every fresh read (the watcher drives it), follows a file that moves between staged and unstaged, and clears the selection when the file is no longer changed. A stale answer (the user clicked another file) is dropped by a request number.
- **Tests:** `ui` has 38 (the 13 before, plus 25 new, 13 of them property tests). Planted bugs, each applied alone then restored, all caught:

| Planted bug | Caught by |
| --- | --- |
| Split: the right cell takes the next added line | `a_replaced_line_sits_beside_its_replacement`, `the_shorter_side_is_padded`, `split_places_each_line_on_its_side_once` |
| Split: the hunk header row is dropped | `a_replaced_line_sits_beside_its_replacement`, `split_row_count_follows_the_runs` |
| Merge ignores word-level changes | `colours_and_changes_overlap_into_runs`, `merged_runs_equal_the_bytewise_answer` |

| The scrollbar thumb has no minimum height | `the_thumb_is_proportional_and_never_tiny`, `the_thumb_stays_in_the_track` |
| A drag is not clamped to the scrollable range | `a_drag_never_scrolls_out_of_range` |
| The list puts staged before unstaged | `unstaged_comes_first_and_empty_sections_vanish`, `a_file_changed_in_both_places_is_listed_twice` |

## What I checked on this laptop

I ran the viewer and the app on fixture repos and drove them with synthetic input, and looked at screenshots (my own check, not a claim that it works for you).

- Split and unified on sample Rust: signs, numbers, syntax colours, word marks (`world`→`Invoke Git`, `i32`→`i64`), the blank cell beside an added line, the no-newline marker, tabs as four spaces.
- **Phase 0 gate finding, closed:** on the 50k-line fixture I pressed the scrollbar track in the middle and dragged to the bottom: every row came up coloured at once. There is no per-chunk request any more; the whole file's spans are parsed once and a row only does a binary search into them.
- **A bug I found by looking:** line numbers were cut to three digits ("496" for 49673). The number column is now as wide as the longest number.
- The app on a repo with a modified, a binary, an untracked, a deleted and a staged file: the list (unstaged 4, staged 2), the code diff, the message for the binary file, the deleted file, and the untracked file. An outside edit of the open file showed up within 3 s (`+2`).
- **Not run by me:** a human drag test of the scrollbar (the synthetic one went top to middle to bottom once), 90 Hz, light theme in the viewer, a huge single line.

## What is unfinished

- **Hunk header height.** The mockup draws a 36px header with the stage buttons. A `uniform_list` needs equal rows, so the header is one `row-diff` (20px) row; the buttons of task 11 should be small controls inside it, or appear on hover. **Proposed:** keep fixed rows; the README already says line height equals row height "so the list can be virtualized with fixed rows".
- No ignore-whitespace toggle (it recomputes the diff), no text selection or copy, no horizontal scroll (long lines are clipped), no image preview, no per-gap "expand" (the context switch is for the whole file).
- The toolbar shows the file name only for a text diff; a message (binary) shows no name. The list highlights the file, so this is minor.
- The performance of the viewer is not benchmarked yet (task 25, the rest).

**Questions and proposed answers**

1. **Parse-time fallback (P0-2 question 1).** The spec says a parse slower than 100 ms renders plain text. The viewer shows plain text first and adds the colours when the parse is done, so nothing blocks, even for the 1.5 MB fixture (about 0.7 s). **Proposed:** replace the 100 ms rule in `diff-engine.md` by "highlighting runs in the background and arrives when ready; the size limits still apply".
2. **Status letters.** I used `M A D R T` as git does and `U` for untracked (git writes `?`). **Proposed:** keep `U`; `?` reads as a missing value.
3. **Which file to open first.** The viewer opens the first changed file on its own when a repo has changes. **Proposed:** keep.

## Anything surprising

- gix's filter pipeline and the status read share the user's config now (task 011 follow-up), so a CRLF checkout shows only its real edits in this viewer.
- `uniform_list` inside a `RenderOnce` works with a closure and a keyed scroll handle, so the file list needed no view of its own.
- GPUI draws font ligatures by default; the diff would have shown `->` as an arrow without the `disable_ligatures` setting.

## Windows checklist for UI changes

`cargo run --release -p ui --example diff` (sample) and `cargo run --release -p ui --example diff -- --fixture` after `cargo xtask fixtures` (50k lines). Then the app on a throwaway repo (`cargo run --release -p app -- C:\path\to\repo`).

1. Sample: the title bar says "Invoke Git diff viewer". You see two columns with line numbers, red and green rows with `−` and `+` signs, purple keywords, green strings, amber numbers, and a darker red or green block on the words that changed. There is a blank dark cell beside an added line. The last line says `\ No newline at end of file` in grey. `->` is two characters, not an arrow.
2. Click "Unified": one column, two number columns, the same colours. Click "10 lines" and "Whole file": more unchanged lines appear; "3 lines" goes back.
3. Fixture: wait about a second. Scroll with the wheel through the whole file; drag the scrollbar thumb from top to bottom, several times, quickly. **Every row must be coloured the whole time, with no flash of plain text and no blank row**, and the drag must feel smooth. Click on the track: the view jumps there.
4. App: open a repo with changes. The left list shows UNSTAGED and STAGED sections with a coloured letter per file; the first file's diff shows on the right. Click each file: the diff changes at once; a binary file says there is no text diff; a deleted file shows only red lines; an untracked file shows only green lines.
5. With a file's diff open, edit that file in another editor and save: within about a second the diff updates and your scroll position stays.
6. On a repo where `core.autocrlf=true` (Git for Windows' default), a file checked out with CRLF that you have not touched must not appear in the list at all, and a file where you changed one line shows only that line.
7. Press Tab: the focus ring moves over the list rows and the toolbar controls.
8. Say whether the grey hunk header rows (`@@ -1,12 +1,13 @@`) look right to you at 20px tall.
