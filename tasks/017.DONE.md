# Task 017 handoff

Backlog task 17: Fetch, pull (merge or rebase), push with `--force-with-lease`, set upstream. **Core half only.** The fetch/pull/push controls and the rejected-push prompt (UI) wait for the Phase 0 gate; row 17 in `docs/PLAN.md` is "Core done".

## What changed

Branch `task-017-sync-rebased`, rebased onto `origin/main` at `53e3cc0` (original `task-017-sync` was from `0dcfb0b`). Lease values come from `RefsSnapshot.refs`, the same snapshot task 15 fills (its `upstreams` map holds ahead/behind, not object ids, so there is no second source).

- **core `ops.rs`:** `WriteRequest` and `GitArgs` gain `Fetch`, `Pull`, `Push`, `SetUpstream`. New `RemoteBranch` (with `tracking_ref()` / `remote_ref()`), `PullMode`, and `Lease { remote_ref, expected }`. A force push is `Push { lease: Some(..) }`: there is no force flag, so a force without an expected value cannot be expressed (law 10). `GitArgs::is_network()`.
- **core `event.rs` / `step.rs`:** `PushRequested` now carries `{ to, force_with_lease, set_upstream }` (was `{ force_with_lease }`); new `FetchRequested`, `PullRequested`, `SetUpstreamRequested`. The branch and, for a force, the lease are taken from the snapshot **at request time** (the value the user reviewed); a fetch that moves the remote-tracking ref before the push runs makes the remote refuse (stale info) rather than overwrite. Refusals (new `Refusal` variants): `NotRead`, `NoBranch` (detached/unborn), `NoRemoteValue(ref)` (force without a known value), `BranchChanged` (checked at dispatch, since the request may have waited), plus `RepoBusy` for a pull during a merge/rebase. Fetch and set-upstream queue like any write; push and pull take an undo point. `Notice::PushRejected` replaces `OpEnded` when a push ends `Failed(Expected)`. `Action` gains `Fetch`, `Pull`, `SetUpstream`. An accepted request now clears a stale `Refused` notice.
- **undo (after rebasing onto tasks 11, 15, 20):** push and pull record their point with `reverse: Reversal::Never(Irreversible::Push | Irreversible::Pull)` (task 20's type; `Irreversible::Pull` is new), so settling and the undo refusal reuse the existing path. `WriteRequest::takes_undo_point()` is false for fetch and set-upstream. A push is `IndexEffect::Untouched`, a pull `Rewrites`.
- **shell `git.rs`:** argv for `fetch --progress -- <remote>`, `pull --progress (--no-rebase --no-edit | --rebase --no-autostash) -- <remote> refs/heads/<b>`, `push --progress [--force-with-lease=<ref>:<oid>] [--set-upstream] -- <remote> refs/heads/<l>:refs/heads/<b>` (no `+`), `branch --set-upstream-to=<remote>/<b> -- <local>`.
- **shell `runner.rs`:** `GitRunner::with_askpass(program)` and `answer(op, answer)` reuse task 16's `AskpassServer` for network ops, mapping prompts to `Event::AuthNeeded`. Cancel, progress and the precondition check are the existing ones.
- **shell `classify.rs`:** `[remote rejected]`, `stale info`, `couldn't find remote ref`, `cannot pull with rebase`, `would be overwritten by merge`, `Not possible to fast-forward` are `Expected`.
- **Tests:** shell lib +4 (argv unit, 3 proptests, one over all request shapes including option-looking names); core `step_props` +3 proptests and 7 unit tests; `crates/shell/tests/sync.rs` 14 integration tests (local bare remote); askpass e2e +2 (fetch and push against the 401 server).

## Questions and proposed answers

1. **Pull and undo.** The spec says undo never rewrites working-tree files, but a pull does. Proposed (implemented): pull leaves an irreversible marker. Alternative: no marker at all.
2. **Push marker needs a saved tree.** Push and pull call `SnapshotForUndo` only so the marker has a tree; wasteful but keeps the entry shape. Proposed: allow `UndoEntry.tree: Option<Oid>` later.
3. **`PushRejected` is derived from the request kind** (a push that ends `Expected`), so "remote does not exist" is also shown as rejected. Proposed: classify push stderr into a typed reason at the shell boundary when the UI needs the distinction.
4. **Lease at request time.** Chosen so the lease is what the user reviewed. If the UI keeps a review screen open across a fetch, it must re-issue the request.
5. `PushRequested` signature changed (needed to name the remote); callers in the UI half must adapt.

## Anything surprising

- `git push`/`pull`/`fetch` accept `--` before the remote, so remote and branch names that look like options are harmless; the proptest includes `-f`, `--force`, `+main`.
- The cancel test needs the slow hook only while a marker file exists, so fixture setup stays fast.
- The sandbox for this agent could not run compound shell commands, so scripts were written to files.
