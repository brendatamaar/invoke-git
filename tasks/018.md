# Task 018

## Goal

Create the pure `graph` crate with the commit-graph lane layout and paging: commits arrive in topological order, page by page, and become row records a renderer can draw without the full history. The GPUI renderer is not part of this task yet.

## Backlog task number

18 in [the plan](../docs/PLAN.md#v01-backlog): "Commit graph: lane layout, paging, renderer". This task is the lane layout and paging half only.

## Files likely touched

- `Cargo.toml` (workspace member)
- `crates/graph/**` (new)
- `docs/PLAN.md` (row 18 status: Core done)

## PRD law numbers

- 14: every commit appears exactly once in the graph, and every parent edge points to a row below its child.

Budget in mind: commit graph scroll at 1M commits (row record about 16 bytes plus edges).

## Constraints

- Pure: no IO, no gix, no clock, no randomness. No dependency on `core` or the spike crates; ids are a generic `Copy + Eq` type.
- Follow "Lane assignment" and "Edge cases" in `docs/spec/commit-graph.md`: merges, octopus merges, several roots, parents outside the loaded pages, shallow boundaries.
- Only `proptest` (dev-dependency) is added.
- Layout state continues across pages; checkpoints every 128 rows let a row's pass-through lanes be rebuilt without the full history.

## Acceptance criteria

- `cargo test -p graph` passes, with property tests over random DAGs for law 14 (one row per commit, edges point down to the parent's row), the lane invariants (no lane holds two commits, parents stay waited for), and paging in any page size equals one big page.
- Each test is shown to fail on a planted bug (listed in DONE.md).
- A timing note for 100k commits in release.
- `cargo xtask check` passes.

## Out of scope

- The GPUI renderer, hover highlight, "+N" marker, ref labels, lazy metadata (the rest of task 18, after the Phase 0 gate).
- The shell's gix walk and shallow-boundary detection (they feed `Commit`).
- Criterion benchmarks (task 25) and Kani proofs (after v0.1).
