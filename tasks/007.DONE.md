# Task 007 handoff

Backlog task 7: App window, open and init repo, repo tabs. Branch `task-007-app-window` (stacked on `task-002-components`; nothing is merged to `main` until the end of Phase 1, as agreed).

## What changed

- **New binary crate `crates/app`** (`invoke-git`, package `app`):
  - `session.rs`: `RepoSession`, one per open repo. It owns the core's `RepoState`, the shell runners (git, staging, discard, undo) and the file watcher. `deliver(event)` steps the core and runs every command it asks for: reads, undo snapshots, staging and discard patches, undo replay and prune on the background executor; git runs on the runner's own threads; cancel and auth answers go to the runner. Every outcome returns as an `Event` on one channel; a task on the UI thread steps the core with each batch (blocking `recv` on a background thread, no polling). This is the driver the harness `App` models, made asynchronous. No business logic.
  - `workspace.rs`: the root view. Tab bar, welcome screen, setup screen, open and init flows, F5 refresh, shortcuts.
  - `tabs.rs` (pure): `Tabs<T>` with an `Active::{Welcome, Repo(i)}` enum. Rules: opening an open repo selects it; closing the selected tab selects its right neighbour, else the left, else the welcome screen; closing another tab keeps the selection.
  - `paths.rs` (pure): `comparable`/`same_repo` treat `C:\Repo`, `c:\repo\`, `C:/Repo` and `\\?\C:\Repo` as one folder (case-insensitive on Windows and macOS).
  - `persist.rs`: the open tabs and the selected one in `%APPDATA%\Invoke Git\tabs.txt` (a text file, format in the module doc). `INVOKE_GIT_DATA_DIR` overrides the folder. A damaged file gives an empty session.
  - `setup.rs` (pure): the words of the blocking setup screen for each `SetupError`.
- **`ui` gained** `TabBar`, `Welcome` and `RepoSummary` (+ the pure `Summary::of(&RepoState)`: head, tracking `↑2 ↓0 vs origin/main`, phase `Rebasing 3/7: 1 conflict`, staged and unstaged counts, lock, stale read). `ui` now depends on `invoke-core`, as the crate diagram says.
- **Shortcuts:** Ctrl+O open, Ctrl+Shift+O initialize, Ctrl+T new tab (welcome screen), Ctrl+W close tab, Ctrl+Tab and Ctrl+Shift+Tab next and previous, F5 refresh. They are **global** (`cx.on_action`), not tied to a focused element. I found this by testing: with shortcuts bound to a `Workspace` key context, Ctrl+W stopped working after clicking "Initialize here", because the clicked button vanished and took the focus with it.
- `invoke-git <folder>...` opens those folders too; a folder that is not a repo shows the same notice as the picker.
- **Tests:** 23 in `app` (tab model, paths, persistence, setup text; 12 are property tests) and 13 in `ui` (adds `Summary`). `cargo xtask check` passes.
- **Planted bugs, all caught** (each applied alone, then restored): see the table below.

## What I checked on this laptop

I ran the release binary on fixture repos in a temp folder and drove it with synthetic mouse and keyboard input, and looked at screenshots. This is my own check, not a claim that it works for you; the checklist below is yours.

- Two repos open as two tabs with badges (2 and 1), the real branch (`trunk`), `0 staged · 1 not staged`, and the window title `repo-two — Invoke Git`.
- A file staged and another edited from outside raised the badge from 2 to 3 within 2 s (the watcher and the read both ran).
- A folder that is not a repo showed "not-a-repo is not inside a git repository." with "Initialize here"; clicking it ran `git init` and opened the repo as `master (no commits yet)`.
- Ctrl+T showed the welcome screen; Ctrl+W closed the tab and the saved file lost it.
- **Not run by me:** the native folder picker (Open and Initialize buttons), a missing or too-old git, a repo whose watcher fails.

## What is unfinished

- A tab shows only a summary until tasks 10, 11 and 18 fill it.
- The auth prompt, askpass and clone wait for task 16.
- No tab drag-to-reorder, no "reopen closed tab".

**Questions and proposed answers:**

1. **Tab persistence is not in the spec.** The PRD says "repo tabs", not that they survive a restart. I added the small text file because every launch would otherwise start empty (SQLite is not in the build table). **Proposed:** keep it; later settings (theme, split or unified diff) can join the same folder.
2. **`RepoState.id` is never filled.** The spec says `id` is the root commit plus the normalized remote URL, but `open()` takes it from the caller and nothing reads them. The harness also passes `None`. **Proposed:** a small shell read (first root commit, `remote.origin.url`) before `open`, in the task that first needs the id (undo persistence or notes).
3. **Global shortcuts.** See above. **Proposed:** keep them global; text inputs (task 14) handle their own keys first.
4. **Default branch of a new repo** is whatever the user's git config says (`master` on this laptop). **Proposed:** keep it. Do not impose `main`.
5. **`INVOKE_GIT_DATA_DIR`** is an addition, for tests and throwaway profiles. **Proposed:** keep.
6. **When the watcher cannot start**, the tab shows a warning and F5 reads again. **Proposed:** keep; revisit if it shows up in real use.

## Anything surprising

- GPUI's `Context::spawn` and `background_executor().spawn` made the event pump simple: one blocking `recv` per repo on a background thread, ended when the session (the last sender) is dropped.
- A stale window title was not a problem: `set_window_title` runs only when the text changes.
- The title bar and window frame are the OS's; the tab bar is ours.

## Windows checklist for UI changes

Run `cargo run --release -p app`, or `cargo run --release -p app -- C:\path\to\a\repo`. Use a throwaway profile if you do not want your tabs saved: `$env:INVOKE_GIT_DATA_DIR = "$env:TEMP\ig-test"` first.

1. First run: the window opens with the "Open a repository" screen, a "New tab" button, no console window in a release build.
2. Click "Open repository…": the Windows folder picker opens. Pick a real repo (your own is fine, it is only read). A tab appears with the folder name, a change count, the branch in a pill, `↑N ↓M vs origin/…` if it has an upstream, and the path. The window title is `<folder> — Invoke Git`.
3. Pick a subfolder of that repo: it opens the repo, not a second tab. Open the same repo again, typed in a different case: the existing tab is selected.
4. Edit a file in the repo from another program: within about a second the change count updates, without clicking anything.
5. Start a rebase or merge with a conflict in a throwaway repo: an amber bar says `Merging: 1 conflict` or `Rebasing 1/2: 1 conflict`.
6. Click "Initialize repository…", pick an empty folder: a tab opens with `master (no commits yet)` (or your default branch name) and `No changes`.
7. Click "Open repository…" and pick a folder that is not in a repo: the amber notice names the folder; "Initialize here" creates the repo and opens it. Check that Ctrl+W then closes the tab.
8. Shortcuts: Ctrl+O, Ctrl+Shift+O, Ctrl+T, Ctrl+W, Ctrl+Tab, Ctrl+Shift+Tab, F5. Hover a tab: its fill lightens. Tab key shows the focus ring on tabs and buttons.
9. Close the app with two tabs open, start it again: both tabs return in the same order with the same one selected. Rename one folder first: it is skipped silently.
10. Set `PATH` so that `git` is not found (for example start the app from a shell with an empty `PATH`): the "Git is required" screen shows, and "Check again" works after fixing it.
