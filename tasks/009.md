# Task 009

## Goal

Create the pure `highlight` crate: a syntax highlighting layer on tree-sitter. File text plus path and attribute data go in, styled byte ranges come out, following [the diff engine spec](../docs/spec/diff-engine.md#highlighting-pipeline):

- pick the grammar from `.gitattributes` `linguist-language`, then file extension, then shebang; no match is plain text
- parse the whole file and run the grammar's highlight query to get captures as byte ranges
- map captures to design token colours through a short fixed list
- give the caller a cheap way to fetch only the spans of the visible window
- refuse files over the "too large" threshold, and let the caller cancel a slow parse

## Constraints

- Pure crate: no filesystem, network, clock, threads or randomness. Parsing on a background thread, the 100 ms limit and the styled-line cache by (blob id, line) belong to the caller.
- The API is synchronous. Cancellation is a `&dyn Fn() -> bool` polled by tree-sitter's progress callbacks, for both parse and query.
- Dependencies: only `tree-sitter` and tree-sitter grammar crates (PRD "Language grammars: tree-sitter grammars"), plus the in-repo `tokens` crate. A grammar with no maintained crate compatible with tree-sitter 0.27 is left out and recorded in DONE.md.
- Colours come only from the `tokens` crate. No hard-coded colours.
- Output spans are sorted, non-empty, non-overlapping, inside the text and on char boundaries, for any input including invalid syntax.

## Acceptance criteria

- `cargo test -p highlight` passes, including:
  - proptests for the detection order over path, attribute and shebang combinations
  - proptests for the span invariants over random text for every grammar
  - one sample per shipped grammar that must produce an expected capture
  - tests for the size limits, cancellation in parse and in query, and `spans_in`
- Each test is shown to fail once by breaking the code on purpose; the results are in DONE.md.
- `cargo check -p highlight --target x86_64-pc-windows-msvc` result is recorded in DONE.md.
- `cargo xtask check` passes on the VPS.

## Out of scope

- The incremental reparse on worktree change, the styled-line cache and the 100 ms timer (caller side, with the diff viewer).
- Markdown inline parsing and embedded languages (code fences, HTML script tags).
- Real syntax colours: `docs/design/README.md` defines none, so the Phase 0 temporary mapping is used and the question goes in DONE.md.
