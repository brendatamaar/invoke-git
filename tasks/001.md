# Task 001

## Goal

Finish the project foundation: the Cargo workspace, CI on GitHub Actions (Windows builds and tests everything; Linux and macOS run the core tests), the license and the README.

## Backlog task number

1 in [the plan](../docs/PLAN.md#v01-backlog): "Cargo workspace, CI (Windows build; core tests on Linux and macOS), license, README".

## Files likely touched

- `.github/workflows/ci.yml` (new)
- `xtask/src/main.rs` (core-only mode for CI)
- `README.md`

## PRD law numbers

None. CI is how every law's owning test will run, but this task adds no law tests.

## Constraints

- Follow the CI matrix in `docs/spec/verification.md` → "Fixtures and CI": Windows runs everything on every push; Linux and macOS run the core suite.
- macOS and Linux builds of the app are on hold, so GPUI must never be built on those runners.
- Use GitHub's own actions only (`actions/checkout`, `actions/cache`) and the rustup that ships on the runners; no new Rust dependencies.
- Branch `task-001-ci` sits on `p0-4-gate`, because the spike crates must build in CI too.
- Pushing to GitHub is outward-facing: ask the user before the first push.

## Acceptance criteria

- `cargo xtask check` and `cargo xtask check --core` pass locally.
- After the user approves a push, the CI run on GitHub is green on Windows, Ubuntu and macOS.

## Out of scope

- Benchmarks (task 25), Quint and the model-based harness (task 24), nightly jobs, release packaging, and the generated fixture repos.
- Already done before this task: the workspace (P0-1), `LICENSE`, the README's GPUI section (P0-1), and `cargo xtask check` (commit `57f072f`).
