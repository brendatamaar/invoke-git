## What changed

Branch `p0-4-gate`, based on `p0-3-commit-graph`.

- **`spike-diff --commit-box`** (`crates/spike-diff/src/commit_box.rs`): a single-line commit message box for the text-input check, adapted from GPUI's `examples/input.rs` at the pinned revision (Apache-2.0).
  - It supports IME composition (inline underline, candidate window placement through `bounds_for_range`), selection by Shift+arrows, Shift+Home/End and mouse drag, double-click word selection, Ctrl+A/C/X/V, and a status line showing length, selection and composition state.
  - It moves by `char` instead of grapheme to avoid adding `unicode-segmentation`.
  - One unit test covers word ranges, including CJK text; it fails if words are limited to ASCII.
- **Automated gate sweeps** on AC power at 60 Hz, all four clean: 60.0 fps in every 5 s window, 0 blank rows, 0 frames over 50 ms, worst frame 19.5–23.8 ms, first paint 35–54 ms. Recorded in `docs/spike-results.md` → "Gate run".
- **`docs/spike-results.md`:** a gate section with the automated results, a table of manual runs waiting for the user, the checklist with the evidence so far, and a note on GPUI's lack of a text-input widget.
- **`tasks/P0-4.md`:** the runbook for the user's part (sections A–E).
- `cargo xtask check` passes.

## Update 2026-11-22 (agent-driven input run)

The agent drove both release windows with synthetic mouse input (wheel 10 s, then three scrollbar drags) on AC at 60 Hz and recorded every stats window in `docs/spike-results.md` → "Agent-driven input runs". Result: 60 fps, 0 blank rows, 0 frames over 50 ms in both, interval p95 17.2–18.4 ms, worst frame 23.5 ms (diff) and 28.1 ms (graph). New finding: about 9,000 rows were painted unstyled (plain ink) during the diff scrollbar drags. The gate outcome is **not decided**; see the three open inputs in the "Gate outcome" section there.
