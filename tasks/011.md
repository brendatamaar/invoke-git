# Task 011

## Goal

The core (non-GPUI) half of the status tree with file, hunk and line staging:

- the status read: a sorted, tree-friendly list of staged, unstaged and untracked changes, read through gix
- pure patch building: a selection (file, hunk or lines) becomes a unified-diff patch for `git apply --cached`, in both directions (stage and unstage), with header recount, CRLF and no-final-newline handled
- core handling: stage and unstage go through the op queue (fresh snapshot, free lock, expected index id, undo point)
- shell execution: `ApplyPatchToIndex` runs `git apply --cached` from stdin and refuses when the index id differs

## PRD law numbers

- 4: staging never changes the worktree file (model-based with real git, core + shell)
- 5: staging every hunk makes the index equal the worktree (same)
- 6: stage then unstage restores the index (same)
- 7: the patch side only (discard is task 13)
- Also rule 4 (disk is the truth: a read never patches state) and rule 5 (every write carries what it expects: `based_on` and `expect_index`).

Owning tests are built as integration tests now; task 24 builds the model-based harness.

## Constraints

- `diff` and `core` stay pure. Patch building is a pure function of a `TextDiff` and a selection.
- Reads go through gix and take no lock; writes go through the system git CLI.
- No new dependencies beyond the PRD table (gix gets its `status` feature; `diff` is an in-workspace crate).
- The UI half is not built: no `ui` or `app` changes.

## Acceptance criteria

- Pure proptests: a generated patch applied to the source text gives exactly the selected change; header counts always match the body; staging every hunk gives the new text and unstaging every hunk gives the old text.
- Core tests: a stage runs only on a fresh snapshot with a free lock, only when its diff was made against the index on disk, carries the expected index id and takes an undo point.
- Integration tests on temp repos (CRLF, no final newline, unicode and spaced paths, new, deleted and empty files): laws 4, 5 and 6 against real git.
- Each new test is shown to fail once by planting a bug (listed in the DONE file).
- `cargo xtask check` passes.

## Out of scope

- Any UI (status tree view, hunk and line checkboxes): the other half of task 11.
- Discard (task 13), commit UI (task 14).
- Binary, symlink, submodule and mode-only changes (they need `git add`, not a text patch).
- Rename detection; the clean filter (`core.autocrlf`) on worktree reads; the model-based harness (task 24).
