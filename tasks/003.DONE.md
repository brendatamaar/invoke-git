# Task 003 handoff

Backlog task 3: Core types: `State`, `Event`, `Command`, `step()` skeleton.

## What changed

Branch `task-003-core-types`, from `main` at `b7f310a`.

- **New crate `crates/core`.** The package is `invoke-core` and the library is `invoke_core` (see Q1). It has no runtime dependencies. `proptest` is a dev-dependency, declared once in the workspace.
  - `ids.rs`: `Oid`, `IndexId`, `BranchName`, `RefName`, `RepoPath`, `RepoId`, `OpId` and `ReadId`. `Oid::from_hex` parses at the boundary. It accepts 40 or 64 hex digits and stores them in lowercase.
  - `state.rs`: `RepoState`, which holds:
    - `snapshot: Snapshot` (`NotRead` or `Read { disk, read }`)
    - `reads: Reads` (`Fresh`, `Pending { latest }` or `Failed { read }`)
    - `ops: OpQueue` (one running op and a FIFO queue)
    - `notice`
  - `DiskState` holds `head`, `phase`, `index`, `status`, `refs` and `lock`. `Head`, `Phase`, `LockState` and `OpPhase` are enums, as the spec sets out.
  - `ops.rs`: `WriteRequest`, typed `GitArgs`, `Progress`, the auth types, `OpOutcome`, `Failure`, `ErrorClass` (the spec's error table), and placeholder `Selection` and `Patch`. `AuthAnswer` redacts itself in `Debug`.
  - `event.rs`: `Event`, `Command`, `ChangeSet`, `Area`, `ReadScope`, `Expect`, `RefValue` and `UndoPoint`.
  - `step.rs`: `open(id)`, which returns the initial state plus the first full read, and `step(state, event)`.
- **What `step` does:**
  - **`DiskChanged`:** emits `ReadState` with that scope and never touches the snapshot. An empty change set does nothing.
  - **`StateRead`:** replaces the snapshot only if the read was requested and is newer than the one applied. The snapshot becomes `Fresh` when the newest requested read lands. Late, older reads are dropped.
  - **`ReadFailed`:** for the newest read, it marks the snapshot `Failed` and sets a notice. For older reads it is ignored.
  - **`CommitRequested`:** queues the commit. A queued write starts only when no write is running, the snapshot is fresh and the lock is `Free`. Starting it emits `SnapshotForUndo` (current branch or `HEAD` with its old value, plus the index id), then `RunGit { args: Commit, expect: { head, index } }`.
  - **Locked repo:** while `index.lock` is held by someone else, writes wait in the queue, as the spec says. They are not refused.
  - **Op lifecycle:** progress updates `Running`. `AuthNeeded` moves the op to `AwaitingAuth`. `AuthAnswered` moves it back to `Running` and emits `AnswerAuth`. Cancel on a running op emits `CancelOp` and moves it to `Cancelling`. Cancel on a queued op removes it. `OpFinished` clears the op, sets a notice and always emits a full `ReadState`. Events for unknown or stale op ids are ignored.
  - **Not handled yet:** `StageRequested`, `UnstageRequested` (task 11), `PushRequested` (17) and `UndoRequested` (12) are refused with `Refusal::NotYetSupported { task }`.
  - **Other events:** `RefreshRequested` triggers a full read. `NoticeDismissed` clears the notice.
- **Tests:** `crates/core/tests/step_props.rs` has 6 proptests with 512 cases each, over random sequences of up to 60 events. Op and read ids are drawn from small ranges, so events hit live state. There are also 2 unit tests (a full commit round trip, auth redaction) and 2 `Oid` parse proptests.

## What is unfinished

- Nothing in scope. Stage, unstage, push and undo are deliberately refused until tasks 11, 17 and 12.

**Spec questions (proposed answers):**

1. **Crate name.** A library named `core` shadows Rust's built-in `core` in every crate that depends on it. **Proposed:** keep the folder `crates/core`, name the package `invoke-core` and the library `invoke_core`. Rename other crates only if they clash too; `diff`, `graph`, `shell` and `highlight` do not. The spec's crate diagram can keep the short names.
2. **`RepoState` shape.** The spec lists `head`, `phase`, `status`, `refs` and `lock` as flat fields. Here they sit together in `DiskState` inside `Snapshot::Read`, so "only `StateRead` replaces the snapshot" is a single assignment, and law 11's comparison is `state.snapshot == fresh read`. The index id is in there too, and `UndoStack` is left out until task 12. **Proposed:** update the spec's struct to this shape.
3. **Auth.** I dropped `Command::ShowAuthPrompt`, because the UI renders the prompt from `OpPhase::AwaitingAuth` (rule 7: the UI only renders state). I added `Event::AuthAnswered` and `Command::AnswerAuth`, so an op can leave `AwaitingAuth`. **Proposed:** update the spec, and task 16 wires the named pipe.
4. **Read ordering.** `ReadState` and `StateRead` carry a `ReadId`, so out-of-order replies cannot regress the snapshot. I added `ReadFailed`, `RefreshRequested` and `NoticeDismissed`. **Proposed:** add these to the spec's event list.
5. **Narrow reads.** The reply to a scoped `ReadState` is still a whole `DiskState`; the scope only tells the shell which parts it must re-read. **Proposed:** task 6 decides whether partial replies are worth it, once the debounce exists to measure it.
6. **`RunGit` carries `expect: Expect { head, index }`.** The spec shows `RunGit { op, args }`, but rule 5 needs the expected values on every write. **Proposed:** update the spec. Task 4 makes the shell check them before running git.
7. **After a failed read,** writes stay blocked until the next `DiskChanged` or `RefreshRequested`. **Proposed:** keep this. The shell or UI can offer Retry (the Network class in the error table).
8. **Task 001 Q2 (core CI jobs fetch Zed):** unchanged. `ui` does not exist yet, so the workspace split is not decided here.

## Anything surprising

- **No Rust on the VPS.** The VPS had no toolchain, so I installed rustup with the stable toolchain (cargo 1.100.0, minimal profile, rustfmt and clippy) into `~/.cargo`. Shells need `source ~/.cargo/env`, or `~/.cargo/bin` on `PATH`.
- **One test missed its planted bug at first.** The first `Oid` rejection test never generated a 39-digit hex string, so it missed that bug. It now also generates hex-only strings near the valid lengths.
- **`prop_oneof!` weights:** if one arm has a weight, every arm needs one.
- **Test time:** the property tests take about 18 s in debug on the VPS. That is fine for now; if CI time matters later, lower the case count.
