# Task P0-4

## Goal

Run the Phase 0 pass/fail checklist on release builds, record the results in `docs/spike-results.md`, and apply the gate rules: does GPUI stay, get one retry, or do we switch to Tauri + React?

## Backlog task number

P0-4, the last of four Phase 0 tasks (P0-1 to P0-4). It covers the measurement protocol, checklist and gate rules in [the plan](../docs/PLAN.md#phase-0--gpui-spike). It is not a v0.1 backlog row.

## Files likely touched

- `crates/spike-diff/src/commit_box.rs`, `crates/spike-diff/src/main.rs` (the text-input check box)
- `docs/spike-results.md` (the gate run)
- `tasks/P0-4.DONE.md`

## PRD law numbers

None.

## Constraints

- Based on `p0-3-commit-graph` (P0-1 to P0-3 are not merged yet).
- Release builds, laptop plugged in, other heavy apps closed, display at 60 Hz (the plan also wants 90 Hz for information).
- The agent runs the automated sweeps. The user does everything that needs hands or eyes: wheel scrolling, scrollbar drags, IME and selection, Task Manager, and the "API felt workable" judgement.
- No new dependencies. The commit box is adapted from GPUI's own `examples/input.rs` at the pinned revision.

## Runbook for the user

Before starting: plug in the laptop, close heavy apps, and check the display runs at 60 Hz (Settings → System → Display → Advanced display). Then build:

```powershell
git switch p0-4-gate
cargo build --release -p spike-diff -p spike-graph
cargo xtask fixtures
```

### A. Diff view (must pass)

1. `cargo run --release -p spike-diff`, then wait about 2 s for syntax colours.
2. Click the readout (top right) to reset it. The console prints `stats reset`.
3. Scroll with the mouse wheel for 10 s: fast, both directions, through the whole file.
4. Drag the scrollbar thumb from top to bottom three times.
5. Copy the last two stats lines from the console. Note any stutter, blank or half-drawn rows, or flashes you saw.
6. Watch Task Manager during the run and note the peak memory.

### B. Commit graph (must pass)

1. `cargo run --release -p spike-graph` and wait until the header shows `200000 commits`.
2. Click the readout to reset it.
3. Scroll with the wheel for 10 s, deeper and deeper.
4. Drag the thumb from top to bottom three times; that covers all 200,000 commits, past the 100k gate depth.
5. Copy the last two stats lines and note what you saw, as in A. Watch Task Manager for peak memory.

### C. Text input (soft check)

1. Run `cargo run --release -p spike-diff -- --commit-box`. The box has focus with an indigo cursor; the grey status line below shows the state.
2. Type `fix: handle CRLF endings`. The text appears; Backspace, Delete, Left, Right, Home and End work.
3. Shift+Left/Right and Shift+Home/End extend a highlighted selection.
4. Drag with the mouse across a word: the selection follows.
5. Double-click `handle`: exactly that word is selected (the status shows `"handle"`).
6. Ctrl+A selects all, Ctrl+C copies, then click at the end and press Ctrl+V. The text is duplicated. Paste into Notepad to confirm the clipboard.
7. Switch to **Microsoft Japanese IME** (Win+Space), type `nihongo`, and press Space to convert:
   - While composing, the text is underlined inline in the box and the status says `composing "…"`.
   - The candidate window appears next to the cursor, not at the screen corner.
   - Enter commits `日本語`, the underline disappears, and the status says `not composing`.
8. Optional: repeat step 7 with **Microsoft Pinyin** (`zhongwen` → `中文`).

### D. 90 Hz (information only)

Switch the display to 90 Hz and repeat A.3 and B.3 for a few seconds each. Send the stats lines; fps should read about 90.

### E. Verdict (must pass: "API felt workable")

Answer in a sentence or two: having seen both prototypes and read the notes in `docs/spike-results.md`, would you choose to keep going with GPUI?

Send me: the stats lines from A, B and D, your observations, peak memory, the C checklist results, and your verdict.

## Acceptance criteria

- `docs/spike-results.md` has every checklist box filled with a result and evidence, and states the gate outcome under the gate rules.
- `cargo xtask check` passes.

## Out of scope

- Fixing anything found in the gate run. A failed box gets its own retry task per the gate rules.
