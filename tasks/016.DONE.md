# Task 016 handoff

Backlog task 16: Clone with progress, cancel and in-app auth prompt (`GIT_ASKPASS`). **Core half only.** The clone dialog and auth dialog (UI) wait for the Phase 0 gate; row 16 in `docs/PLAN.md` is "Core done".

## What changed

Branch `task-016-clone`, from `origin/main` at `2ba7289`.

- **Where a clone lives in the core (decision):** a clone runs before a repo exists, so it does not go into `RepoState`/`OpQueue`. `invoke_core::clone` is a separate small pure machine: `step_clone(CloneState, CloneEvent) -> (CloneState, Vec<CloneCommand>)`. Phases mirror `OpPhase` (`Running{progress}`, `AwaitingAuth`, `Cancelling`) plus `Ended(OpOutcome)`, which stays until `Dismissed`. Several clones may run at once. Invalid requests (empty URL or folder) end at once with an `Expected` failure and no command. When a clone succeeds, the app calls `step::open` on the new folder (not done here). Existing `Event::AuthNeeded` / `AuthAnswered` / `Command::AnswerAuth` are for ops inside an open repo and stay the path for fetch/push (task 17); clones use the same shapes in `CloneEvent` / `CloneCommand`.
- **`crates/askpass`** (new, std only; lib plus bin `askpass`): the helper git and ssh run. It reads the prompt from argv[1], the pipe address and token from `INVOKE_GIT_ASKPASS_ADDR` / `INVOKE_GIT_ASKPASS_TOKEN`, asks the shell, prints the answer plus newline on stdout and exits 0; on cancel, wrong token or no server it exits 1 with empty stdout. The lib holds the length-prefixed wire protocol (size limits, never panics on garbage) and the client (Unix socket; on Windows the pipe is opened like a file, retrying on `ERROR_PIPE_BUSY`).
- **`shell::askpass::AskpassServer`:** Unix socket in a private 0700 folder (removed on shutdown), or a named pipe on Windows (`windows-sys`; first instance uses `FILE_FLAG_FIRST_PIPE_INSTANCE`, remote clients rejected, next instance created before the current client is served). A 128-bit per-op token comes from std's randomly seeded hasher (no new dependency). Prompts are asked one at a time; `notify(AuthPrompt)` is a callback, so task 17 can reuse the server and emit `Event::AuthNeeded`. `classify_prompt` maps prompt text to `AuthKind` (unknown counts as Password, i.e. masked). `shutdown()` cancels waiting prompts. `env(program)` gives `GIT_ASKPASS`, `SSH_ASKPASS`, `SSH_ASKPASS_REQUIRE=force`, the address and token (plus a dummy `DISPLAY` for old OpenSSH when unset).
- **`shell::CloneRunner`** (`clone.rs`): `execute(CloneCommand, Sender<CloneEvent>)`, plus `run` / `cancel` / `answer`. Runs `git -c ... -c protocol.ext.allow=never clone --progress -- <url> <target>`. The spawn/drain/progress/cancel code was extracted from `runner.rs` into `run_child` (a progress sink replaces the hard-wired `OpProgress`), so `RunGit` and clones share it. Exactly one `Finished` per job. Refuses a relative or non-empty target (`Expected`) before running. Cleanup after failure or cancel: removes the topmost folder the clone created (so leading folders such as `work/deep` go too); if the target was an existing empty folder it is emptied and kept.
- `classify.rs`: added clone markers (`already exists and is not an empty directory`, `does not exist`, `does not appear to be a git repository`, `Repository not found`) to `Expected`.
- Tests: core 6 new (5 unit, 1 proptest); askpass 4 lib (3 proptest) plus 6 e2e; shell 7 clone integration, 1 cleanup unit, 2 classifier/prompt unit.

## Questions and proposed answers

1. **Cancelling just the prompt.** `AuthAnswer` has no "cancel" variant, so the auth dialog's Cancel button should send `CancelRequested` for the whole job (as the e2e test does). Proposed: keep it so; the helper can still exit non-zero on a server shutdown.
2. **"Nothing written to disk" on Unix.** The socket is a file system node in a 0700 temp folder, holding no secrets; std has no portable abstract sockets. Proposed: accept; the spec's intent (no secrets on disk) holds.
3. **Credential helpers.** A configured credential helper (Git Credential Manager) may show its own window before askpass is asked. Left untouched per "inherit the user's config".
4. **Helper binary name.** `askpass`; the installer should ship it as `invoke-git-askpass` or similar, which the runner allows since the path is passed in.

## Anything surprising

- Cargo allows the cycle `shell -> askpass` (lib) and `askpass` dev-dependency `shell`; used so the end-to-end tests get `CARGO_BIN_EXE_askpass`. The e2e tests live in `crates/askpass/tests/e2e.rs` for that reason, so `cargo test -p shell` alone does not run them.
- No real network is needed to test the Auth class: a throwaway `127.0.0.1` HTTP server answering 401 makes real git call askpass for username then password and then fail with `Authentication failed`.
- A slow clone is made with `uploadpack.packObjectsHook` in the isolated global config (honoured because global config is protected config).

## Follow-up: Windows cancel fix (coordinator)

The first Windows CI run failed `cancel_mid_clone_leaves_no_folder`: the slow `packObjectsHook`'s `sleep` outlived the cancel. The job object from task 4 allowed breakaway (`JOB_OBJECT_LIMIT_BREAKAWAY_OK`). The likely cause is that the MSYS runtime behind Git for Windows' `sh` starts children outside a job that allows breakaway, though this hasn't been confirmed. The job now uses default limits, with no breakaway. The trade-off is that a git child that insists on leaving the job (a daemon such as fsmonitor) fails to start, and git runs without it. **Question:** if fsmonitor matters on Windows, run the daemon outside our jobs. For example, start it once with `git fsmonitor--daemon start` from the shell, outside any op.

## UI half (added 2026-11-22, branch `task-016-clone-ui`)

- **`app::clone_view`.** `Clone repository…` on the welcome screen opens the dialog in its place. Fields: address, `Clone into` (a folder picker; default `Documents` in the home folder, else the home folder) and a folder name (empty means the name from the address: `https://host/o/r.git`, `git@host:o/r.git`, `…/r/`, `C:\x\r` all give `r`); the line under them says which folder will be created. `Clone` is disabled until all three are usable. A name that Windows, macOS or Linux would refuse (`a:b`, trailing dot, ...) is not accepted.
- **Phases are the core's** (`ClonePhase`), drawn by `clone_view::screen`: connecting or `Receiving objects: 45%` with a progress bar (only when git gives a total), the credential prompt, "Cancelling and cleaning up…", failure (the class's words from `notice::failure_message` plus the last line git printed, e.g. `fatal: Authentication failed`), "Cancelled. Nothing was left in the folder." and "Done" (the dialog closes and the repo opens through the same `open_path` as `Open repository…`). After a failure or cancel the form comes back with what was typed.
- **`app::auth_prompt`** (reusable for fetch, pull and push in task 17): heading by kind (user name, password, passphrase, unknown host), git's own prompt text, a field (masked for password and passphrase), `Continue` (Enter does too) and `Cancel`; for an unknown host `Trust and continue` answers `yes` and `Cancel` answers `no`. A line says the answer goes to git for this operation only and is not stored. Cancel on a field cancels the whole job (decision 1 of the core half).
- **Masked field (`ui::TextEditor::masked`).** One line, shown as stars (one byte of star per byte of text, so every cursor offset still works); Copy does not put it on the clipboard (Cut deletes without copying). The IME and the platform text input still see the real text, as for any password box.
- **Helper binary.** The dialog looks for `askpass(.exe)` next to the app. In `target\debug` and `target\release` it exists after `cargo build --workspace` or `cargo build -p askpass`, but **`cargo run -p app` alone does not build it**; if it is missing the dialog says so (a banner with the path and the command) and public repositories still clone. Proposed for the installer task: copy it next to the exe; proposed for development: an xtask `run` that builds both.
- **`notice::headline`** (new): the line shown beside the words is now the last non-empty line git printed, not the first (the first was `Cloning into ...` or git's progress). The repo bar uses it too.
- **Tests:** `app` 58 (name from address, folder names, screen per phase, zero total, headline, prompt wording and host-key answers), `ui` +2 (mask).
- **Planted bugs, all caught:** `.git` kept in the name and trailing slash kept (`the_folder_name_comes_from_the_address`), a cancelled job shown as done (`the_screen_follows_the_phase_of_the_job`), a zero total shown as a percentage (`a_total_of_zero_shows_no_percentage`), headline is the first line (`the_headline_is_the_last_line_git_printed`), host-key `y` instead of `yes` (`a_host_key_answer_is_the_word_ssh_waits_for`), the mask shows the text (`a_secret_shows_only_stars` and the offsets property). One planted check (`name != ".."`) survived because it was redundant with the trailing-dot rule; I removed the redundant lines.
- **I ran it on this laptop** (a fresh home folder so the tabs file was empty): (1) cloned a local repository through the dialog: the folder was created in the default `Documents`, the repo opened in a tab with `main` and `origin/main`; (2) cloned `http://127.0.0.1:8765/x.git` served by a script that answers 401 to everything: the dialog showed `Git needs a user name` with git's text `Username for 'http://127.0.0.1:8765':`, then, after `alice` and Enter, `Git needs a password` with the field showing stars; after a password the dialog showed `Authentication failed.` and no folder was left; (3) `Cancel` on the user name prompt gave `Cancelled. Nothing was left in the folder.`, no folder, and no stray `git` or `askpass` process.
- Not run by me: a real private repository (HTTPS token or SSH key), an ssh host-key question, a passphrase prompt, a progress bar on a large repository (the local clone was too fast to see one), Cancel while the progress bar shows, the folder picker, a clone into an existing empty folder, a very long address.

### Windows checklist (tasks 2, 7, 10, 11, 14, 15, 18, 19, 20 apply too)
