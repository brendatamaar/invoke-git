# Task 016 handoff

Backlog task 16: Clone with progress, cancel and in-app auth prompt (`GIT_ASKPASS`). **Core half only.** The clone dialog and auth dialog (UI) wait for the Phase 0 gate; row 16 in `docs/PLAN.md` is "Core done".

## What changed

Branch `task-016-clone`, from `origin/main` at `2ba7289`.

- **Where a clone lives in the core (decision):** a clone runs before a repo exists, so it does not go into `RepoState`/`OpQueue`. `invoke_core::clone` is a separate small pure machine: `step_clone(CloneState, CloneEvent) -> (CloneState, Vec<CloneCommand>)`. Phases mirror `OpPhase` (`Running{progress}`, `AwaitingAuth`, `Cancelling`) plus `Ended(OpOutcome)`, which stays until `Dismissed`. Several clones may run at once. Invalid requests (empty URL or folder) end at once with an `Expected` failure and no command. When a clone succeeds, the app calls `step::open` on the new folder (not done here). Existing `Event::AuthNeeded` / `AuthAnswered` / `Command::AnswerAuth` are for ops inside an open repo and stay the path for fetch/push (task 17); clones use the same shapes in `CloneEvent` / `CloneCommand`.
- **`crates/askpass`** (new, std only; lib plus bin `askpass`): the helper git and ssh run. It reads the prompt from argv[1], the pipe address and token from `INVOKE_GIT_ASKPASS_ADDR` / `INVOKE_GIT_ASKPASS_TOKEN`, asks the shell, prints the answer plus newline on stdout and exits 0; on cancel, wrong token or no server it exits 1 with empty stdout. The lib holds the length-prefixed wire protocol (size limits, never panics on garbage) and the client (Unix socket; on Windows the pipe is opened like a file, retrying on `ERROR_PIPE_BUSY`).
- **`shell::askpass::AskpassServer`:** Unix socket in a private 0700 folder (removed on shutdown), or a named pipe on Windows (`windows-sys`; first instance uses `FILE_FLAG_FIRST_PIPE_INSTANCE`, remote clients rejected, next instance created before the current client is served). A 128-bit per-op token comes from std's randomly seeded hasher (no new dependency). Prompts are asked one at a time; `notify(AuthPrompt)` is a callback, so task 17 can reuse the server and emit `Event::AuthNeeded`. `classify_prompt` maps prompt text to `AuthKind` (unknown counts as Password, i.e. masked). `shutdown()` cancels waiting prompts. `env(program)` gives `GIT_ASKPASS`, `SSH_ASKPASS`, `SSH_ASKPASS_REQUIRE=force`, the address and token (plus a dummy `DISPLAY` for old OpenSSH when unset).
- **`shell::CloneRunner`** (`clone.rs`): `execute(CloneCommand, Sender<CloneEvent>)`, plus `run` / `cancel` / `answer`. Runs `git -c ... -c protocol.ext.allow=never clone --progress -- <url> <target>`. The spawn/drain/progress/cancel code was extracted from `runner.rs` into `run_child` (a progress sink replaces the hard-wired `OpProgress`), so `RunGit` and clones share it. Exactly one `Finished` per job. Refuses a relative or non-empty target (`Expected`) before running. Cleanup after failure or cancel: removes the topmost folder the clone created (so leading folders such as `work/deep` go too); if the target was an existing empty folder it is emptied and kept.
- `classify.rs`: added clone markers (`already exists and is not an empty directory`, `does not exist`, `does not appear to be a git repository`, `Repository not found`) to `Expected`.
- Tests: core 6 new (5 unit, 1 proptest); askpass 4 lib (3 proptest) plus 6 e2e; shell 7 clone integration, 1 cleanup unit, 2 classifier/prompt unit.

## Questions and proposed answers

1. **Cancelling just the prompt.** `AuthAnswer` has no "cancel" variant, so the auth dialog's Cancel button should send `CancelRequested` for the whole job (as the e2e test does). Proposed: keep it so; the helper can still exit non-zero on a server shutdown.
2. **"Nothing written to disk" on Unix.** The socket is a file system node in a 0700 temp folder, holding no secrets; std has no portable abstract sockets. Proposed: accept; the spec's intent (no secrets on disk) holds.
3. **Credential helpers.** A configured credential helper (Git Credential Manager) may show its own window before askpass is asked. Left untouched per "inherit the user's config".
4. **Helper binary name.** `askpass`; the installer should ship it as `invoke-git-askpass` or similar, which the runner allows since the path is passed in.

## Anything surprising

- Cargo allows the cycle `shell -> askpass` (lib) and `askpass` dev-dependency `shell`; used so the end-to-end tests get `CARGO_BIN_EXE_askpass`. The e2e tests live in `crates/askpass/tests/e2e.rs` for that reason, so `cargo test -p shell` alone does not run them.
- No real network is needed to test the Auth class: a throwaway `127.0.0.1` HTTP server answering 401 makes real git call askpass for username then password and then fail with `Authentication failed`.
- A slow clone is made with `uploadpack.packObjectsHook` in the isolated global config (honoured because global config is protected config).
