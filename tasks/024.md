# Task 024

## Goal

Make every one of the 14 laws in the PRD map to one owning test that cannot silently disappear, and add the model-based harness: random sequences of user and outside actions run on the real core and shell and on plain git in a twin repo, compared after every step. Run it in CI (256 sequences on every push, 10,000 nightly) and write the three Quint specs.

## PRD law numbers

All 14. Laws 1-3 (diff), 7 (discard, task 13), 10 (push, task 17) and 14 (graph) keep their own tests; the table only names them. The harness owns 4, 5, 6, 8, 9 and 11, and also checks 12 on the real shell. Laws 12 and 13 keep their runner tests as owners.

## Constraints

- Test-only code: the harness crate has no library users and adds no behaviour to the product crates. It changes none of `core`, `shell`, `diff`.
- Tests use only generated temp repos with `GIT_CONFIG_NOSYSTEM=1` and an empty `GIT_CONFIG_GLOBAL`. Fixed author, committer and dates make the same commit have the same id in the app repo and the twin. No `canonicalize` on Windows.
- The git CLI is the oracle. The app repo is inspected without writing to it (`GIT_OPTIONAL_LOCKS=0`, `ls-files`, `for-each-ref`, plain file reads).
- Only one new dependency, `proptest-state-machine`, which is in the PRD's build-vs-library table.
- What the core cannot do yet (push, fetch, pull, rebase, cherry-pick, discard, conflict resolution) is not generated; it is listed in DONE.md.

## Acceptance criteria

- A test fails when an owning test of any law is renamed, ignored or deleted, when an inline check of the harness is dropped, or when the PRD or the verification spec stops listing 14 laws. Laws whose backlog task is not merged (7 and 10) have a named placeholder that fails the day the real test appears under that name.
- The harness generates edits, creations, deletions and renames of files (CRLF, no final newline, unicode names and content), stage and unstage of files, hunks and lines, commit and amend, branch create, switch, rename and delete, stash save, apply, pop and drop, undo, and outside `git commit -a`, `git checkout` and a held `index.lock`.
- After every step it compares HEAD, every ref, the index entries, the stash list and every worktree file between the app repo and the twin, the app's `RepoState` with a fresh read and with `git status` (law 11), the saved undo points with the undo stack, and checks that every refusal or failure has a stated reason.
- A failing sequence is shrunk by proptest and printed as a list of plain git commands.
- The case count comes from `INVOKE_HARNESS_CASES` (default 256, up to 40 steps). A nightly workflow runs 10,000 on Linux.
- Each check is shown to fail by a planted bug (listed in DONE.md), and the printed replay is shown.
- The three Quint specs are written, each under a few hundred lines, and checked in a workflow.
- `cargo xtask check` passes.
