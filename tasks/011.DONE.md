# Task 011 handoff

Backlog task 11: Status tree with file, hunk and line staging. This is the **core half** only. Branch `task-011-staging`, from `origin/main` at `0dcfb0b`. `docs/PLAN.md` row 11 is now "Core done".

## What changed

- **Patch building (pure, `diff` crate).** New `crates/diff/src/patch.rs`: `build_patch(&TextDiff, &PatchSpec, &Pick) -> Result<Option<String>, PatchError>`. `Pick` is `File`, `Hunk(i)` or `Lines { hunk, lines }`; `Direction` is `Stage` (diff is index to worktree) or `Unstage` (diff is HEAD to index). It follows the table in `diff-engine.md`: recount of every header, new starts shifted by the net change of earlier hunks in the patch, removals before additions inside a run, CRLF kept byte for byte, `\ No newline at end of file` placed after every line with `Eol::None`, new-file and deleted-file headers (with mode), header-only patches for empty files, C-style quoting for odd path characters. I chose the `diff` crate (not `core`) because the spec lists "patch building, staging" under `diff` and `core` should stay free of file contents.
- **Core.** `Event::StageRequested` / `UnstageRequested` now carry a `StageRequest { selection, patch, based_on }` (`Selection` stays, for labels). `WriteRequest::Stage` / `Unstage` go through the op queue like a commit: they wait for a fresh snapshot and a free `index.lock`, are refused with `Refusal::StaleDiff` when `based_on` is not the index on disk at dispatch, and emit `SnapshotForUndo` (label such as "Stage 3 lines in a.rs", no refs, index only) then `ApplyPatchToIndex { expect_index }`. An empty patch is refused at once (`Refusal::NothingSelected`). A finished stage becomes an undo point after the next fresh read, like a commit. `StatusSnapshot::from_entries` sorts by path (byte order, so each directory is a contiguous run), merges halves and drops empty entries; `staged()` and `unstaged()` iterate the two sections.
- **Shell.** `status.rs`: the status read through gix (`TreeIndex` for staged, `IndexWorktree` for unstaged and untracked, untracked reported file by file, ignore rules honoured, no rename detection, conflicts left to the phase). It takes no lock and does not write the index back. `read_state` now fills `status` (opened through the worktree path, see "surprising"). `staging.rs`: `StagingRunner::apply` (refuses on `index.lock` or a different index id, runs `git apply --cached --whitespace=nowarn --check -` and then the same without `--check`, patch on stdin) and `load_inputs` (reads the old and new text of a file for `IndexToWorktree` or `HeadToIndex` through gix and plain file reads, with the index id read before and after; binary, non-UTF-8, symlink, submodule and intent-to-add files come back as `NotText`).
- **Dependencies.** `gix` gets the `status` feature in `shell` (gix is in the PRD table; `Cargo.lock` grows by gix-status, gix-dir and friends). `diff` is a dev-dependency of `shell`, for the tests only.
- **Tests.**
  - `crates/diff/tests/patch.rs` (14): an independent patch reader/applier (follows header counts, matches lines byte for byte, checks each hunk's new start against the lines already produced) with proptests for exact selected change (512 cases, both directions, oracle walks the whole file by the spec table), stage-all = new text, unstage-all = old text, hunk pick = all its lines, header counts; plus examples for the marker, CRLF, widening, new/deleted/empty files, quoting.
  - `crates/core/tests/stage_props.rs` (10): the queue path, stale refusal at request and at dispatch, lock wait, empty patch, undo of a stage, failed stage leaves no point, "runs iff the diff matches the index" property, status snapshot sorted/merged/directory-contiguous property. `step_props.rs` now generates `StageRequest`s.
  - `crates/shell/tests/staging.rs` (19): real core + real shell + real git as oracle. Law 4 and 5 (`law_4_and_5_every_hunk_staged`, 48 random files; CRLF, no-final-newline, unicode and spaced paths, new, deleted and empty files, executable mode) and law 6 (`law_6_stage_then_unstage_restores_the_index`, random line selections, compared by `git ls-files -s`), undo of staging, refusals (stale diff, lock, moved index, patch that does not fit), status read (sorted, ignores, staged+unstaged, staged delete + untracked, unborn repo, lock-free and does not touch the index file).
- Fixed along the way: an existing test (`git_file_pointing_elsewhere_is_followed`) exposed that opening by git dir gives gix no worktree when the git dir is elsewhere; the status read opens through the worktree path (`precondition::open_with_worktree`).

## Spec questions, with proposed answers

1. **Who builds the patch?** The spec says "the core builds it" but the core holds no file contents. I made the UI build it with `diff::build_patch` from the diff it shows, and send it in the request together with the index id the diff was made against (`based_on`). The core refuses when that index is not the one on disk. Proposed: record this in `core-design.md` (and replace `Selection` there by `StageRequest`).
2. **Widening at an unterminated last line.** A line without a final newline cannot be followed by another line, so staging only a line after it is not expressible. I widen the selection: stage also takes the removal of the unterminated line and its newline-terminated twin; unstage of the removal of an unterminated line also takes the added lines after it. Proposed: add this to "Line staging" in `diff-engine.md`; the alternative is to refuse such a selection with a message.
3. **Global git config is ignored by reads.** The shell opens repos with `gix::open::Options::isolated()`, so a user's global excludes file (`core.excludesFile`) does not hide untracked files in the status, and `core.autocrlf` is not applied. Proposed: for status, open with the user's config but guard tests with `GIT_CONFIG_GLOBAL`.
4. **`core.autocrlf` / clean filters.** `load_inputs` reads the worktree file raw. With `core.autocrlf=true` (Git for Windows' default) every line of a CRLF file differs from the index blob, so the diff and the staged result are wrong. Proposed: run the worktree text through gix's filter pipeline (`to_git`) in `load_inputs`; needs the gix `worktree-mutation`/filter feature; do it before the Windows UI test.
5. **Index id as freshness.** An unchanged index id does not prove the worktree file is unchanged since the diff was loaded (the patch only touches the index, so it cannot corrupt anything, but it can stage something slightly different from what is on screen). Proposed: the watcher's `DiskChanged(Worktree)` refreshes the open diff, as for the index.
6. **Path text.** `RepoPath` is a `String`; non-UTF-8 paths are converted lossily and cannot be staged. Proposed: accept (Windows paths are UTF-16 anyway).

## Follow-up 2026-11-22: `core.autocrlf` and the user's git config (questions 3 and 4)

Checked on the Windows laptop, where `core.autocrlf=true` is set globally. **The problem was real, in two places:**

1. **Diff:** with `core.autocrlf=true` in the repo's own config, the status read was right (gix applies repo-local config and filters) but `load_inputs` read the worktree file raw, so the new side kept CRLF and every line differed from the LF index blob.
2. **Status:** with the setting only in the user's config, the shell opened repos `isolated()`, so it never saw it, and every CRLF checkout showed as modified.

**What changed**

- `load_inputs` runs the worktree file through gix's filter pipeline (`filter_pipeline().convert_to_git(...)`), the same conversion `git add` does, so the new side is the text that would be staged. A CRLF checkout of an LF blob shows only the real edits; the patch is LF like the index.
- The blob id of the worktree side (`new_blob`, what discard and its undo compare) stays the hash of the file's **raw bytes**. I first changed it to the filtered bytes and caught the mistake before it shipped: discard would have been refused for every CRLF file.
- `shell::use_user_config(true)` makes reads honour the user's and the system's git config. It is off by default, so every existing test stays machine independent; `app` switches it on at start-up. Repo-local config always applied.
- Checked by hand: `git apply` (what discard uses) on a CRLF worktree file with an LF patch gives a CRLF result and a clean status under `autocrlf=true`, so discard is fine. A discard test under `autocrlf` through the real runners can join the task 13 UI checks.
- Docs: `core-design.md` (environment additions `LANGUAGE=en`, `GIT_EDITOR=true`, git config in reads, stale locks, undo replay and `HEAD`, switch undo rewrites files, the undo store timing, `StageRequest`), `diff-engine.md` (filters and the widening rule), `PRD.md` (SQLite via `rusqlite` approved), `PLAN.md` (task 22 also persists undo).
- Tests: `crates/shell/tests/autocrlf.rs` (6: status agrees with git, the diff shows only the edit, the patch is LF, real git stages the line into an LF index, `autocrlf=false` keeps CRLF as a change, the new blob is the raw file) and `crates/shell/tests/user_config.rs` (1: ignored by default, honoured when asked). Planted bugs: filtering skipped (3 tests fail), user config never read (the user config test fails). All other shell tests still pass.

**Answers recorded** (from the proposals above): question 1 is now in `core-design.md`; question 2 is in `diff-engine.md`; questions 3 and 4 are done; question 5 (refresh the open diff on `DiskChanged(Worktree)`) is for the diff viewer, task 10; question 6 is accepted.

This matters for dogfooding (images, lock files). **Proposed:** add `GitArgs::Add { paths }` and `RestoreStaged { paths }` to the core and shell with the same expected-index guard and undo point, as a small task before task 26.

- The line checkboxes are plain boxes, not focusable; the tree rows are.

### Windows checklist (tasks 2, 7, 10, 18 apply too)

`cargo run --release -p app -- C:\path\to\a\throwaway\repo` with a few modified files, one new file and one nested folder.

1. The left pane shows UNSTAGED and STAGED sections with `Stage all` or `Unstage all`; folders have a chevron, a checkbox and a file count; click a chevron to fold. Click a file: its diff shows on the right.
2. Click a file's checkbox: it moves to STAGED (`git status --short` shows `M ` for it); click again in STAGED: it moves back. Click a folder's checkbox: all its files move. `Stage all` and `Unstage all` move everything, one file after the other.
3. In a diff, each changed line has a small checkbox. Tick one removed and the matching added line: a `Stage 2 lines` button appears in that hunk's header; press it: only those lines are staged (check with `git diff --cached`).
4. `Stage hunk` stages the whole hunk. In a staged file the buttons read `Unstage hunk` and `Unstage N lines`.
5. After each stage, an `Undo` button with the operation's name appears at the top; press it: the index goes back (the files change place again). Edit a file in another editor between a stage and its undo: the undo is refused with a message and nothing changes.
6. Stage something while another program holds `.git\index.lock` (run `type nul > .git\index.lock`): a yellow bar says the repository changed or another git process is running, with Dismiss. Delete the lock afterwards.
7. A binary file's checkbox shows a bar saying it cannot be staged yet.
8. On a `core.autocrlf=true` machine, stage one line of a file with CRLF endings: only that line changes in the index (`git diff --cached`), no whole-file change.
