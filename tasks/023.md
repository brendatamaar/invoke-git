# Task 023

## Goal

The core (non-GPUI) half of conflict resolution with continue and abort:

- core: model the flow with enums. Each conflicted file is `Unresolved(kind)` or `Resolved`, derived from the fresh snapshot. `ContinueRequested` runs only when every file is Resolved (refused with a reason and a count otherwise), `AbortRequested` is allowed whenever a merge, rebase, cherry-pick or revert is paused, `SkipRequested` is for a rebase, and `ResolveFileRequested { path, choice }` takes ours, theirs or the worktree file as it is. All go through the op queue, are planned against the snapshot they run on, and carry the operation (and rebase step) the user saw.
- shell: argv for `merge|rebase|cherry-pick|revert --continue|--abort`, `rebase --skip`, taking a side whole (`checkout --ours|--theirs`, then `add`), deleting a file for a missing side (`rm`) and staging a file (`add`); git never waits for an editor; the "resolved" paths are read from the index's resolve-undo record; a read of the three stages of a conflicted file (base, ours, theirs) through gix, text only, binary flagged.

## PRD law numbers

- 8: an abort puts refs, index and files back exactly.
- 9: continuing, skipping and aborting move only the branch the operation is on.
- 12: the conflict flow waits for `index.lock` like every other write.
- 13: a running abort or continue is not killed half way; git's own resumable state is the only state in between.

## Constraints

- `core` stays pure: no IO. Argv building and the stage reads live in `shell`.
- Reads through gix, writes through the git CLI. The one exception is the resolve-undo record, which gix does not expose: it is read from the raw index file in `shell` (std only).
- No new dependencies.
- Tests use temp folders and generated repos with system and global git config shut out; never the user's repos.

## Acceptance criteria

- Property tests: Continue runs only when every file is Resolved, and a refusal says how many are left; Abort is allowed in every paused phase; Skip only for a rebase; nothing is written on a stale or locked snapshot; a request for one rebase step is refused on the next; network writes are refused while paused.
- Integration tests on temp repos with real conflicts: merge, rebase (three steps, step n/m advances, skip), cherry-pick, revert: resolve ours, theirs and by hand, continue, skip, abort (HEAD, branch, index, status and files exactly as before); delete/modify in both directions; binary conflict flagged; CRLF content byte for byte; glob characters in paths; an editor that fails does not stop a continue.
- Each new test fails once against a planted bug.
- `cargo xtask check` passes.
