# Task 006

## Goal

Add the file watcher: watch the worktree and the git dirs, classify each changed path into an `Area`, coalesce bursts with a 50 ms quiet period, and send one `Event::DiskChanged` per burst.

- Pure, in `invoke_core::watch`: `WatchRoots::classify(path) -> Option<Area>` (Windows separators and case handled) and `Debounce` (`push(now, areas)`, `poll(now)`, `deadline()`), with time passed in.
- IO, in `shell::watch`: `RepoWatcher::start(&Discovered, Sender<Event>)` using `notify`, a thread that feeds the debouncer from a real clock, and ignore rules through gix.

6 in [the plan](../docs/PLAN.md#v01-backlog): "File watcher with debounce, emitting refresh events".

## PRD law numbers

- 11: the app's state equals the state derived from `.git` after the next watcher event. The watcher never carries data, only "something in this area changed"; the core then reads from disk.

## Constraints

- Core stays pure: no clock, no disk. Time is an input.
- Changes inside `objects/` never produce an event. Worktree paths that git ignores produce none.
- Dependencies: `notify` (in the PRD table). gix gains its `excludes` feature (same crate, already in the table).
- Tests use generated temp repos with global and system git config isolated.

## Acceptance criteria

- Property tests: never emits before 50 ms quiet; emits exactly the union of areas seen; never loses a change; `objects/` never classifies; classification ignores case and separator style on case-insensitive roots.
- Integration tests: one worktree write gives one `DiskChanged{Worktree}`; a commit gives Refs and Index; a branch switch gives Head; a marker file gives InProgress; 100 writes give one event; writes under `.git/objects` and ignored paths give none; dropping the watcher stops events.
- Each new test shown to fail against a planted bug.
- Windows target check and clippy pass; `cargo xtask check` passes.

## Out of scope

- Turning `DiskChanged` into `ReadState` (the core's `step` already does), wiring to the app (7), and narrowing the read in the shell (it still returns a whole `DiskState`).
