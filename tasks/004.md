# Task 004

## Goal

Create the `shell` crate's command runner, which runs the system git for the core's write commands:

- find git and check that it is ≥ 2.40
- turn typed `GitArgs` into argv, with only output-formatting `-c` options and `GIT_TERMINAL_PROMPT=0`
- before running, check each write's expected head and index against disk, and check `index.lock`
- parse `--progress` stderr into `OpProgress` events
- cancel by killing git's whole process tree: a job object on Windows, a process group on Unix
- classify every outcome once into the core's error classes and report it as exactly one `OpFinished`

## PRD law numbers

- 12: a write never runs while `index.lock` exists. The shell checks before spawning git, and git's own lock refusal is classified as `PreconditionChanged`.
- 13: cancel kills the whole tree and reports `Cancelled`. The core then re-reads (task 3). The owning "cancel at random points" test needs the network and multi-step ops of tasks 17 and 23. This task covers cancel during a hook.
- Rule 5 (every write carries what it expects): a mismatch is refused before git runs.

## Constraints

- The shell holds no business logic. It runs commands and reports events. Parsing at this boundary (version, progress, stderr classification) lives here as pure functions with tests.
- Reads go through `gix` (the expected-head check). Writes go through the git CLI.
- The user's environment and git config are inherited. The only additions are:
  - `GIT_TERMINAL_PROMPT=0`
  - `LANGUAGE=en`, so stderr can be classified; it affects message language only
  - `-c core.quotepath=false -c color.ui=false`
- On Windows, spawn with `CREATE_NO_WINDOW`, so no console flashes.
- New dependency: `windows-sys`, Windows only (approved). `gix` is already in the table. No other new dependencies; temp folders in tests use std only.
- Tests use generated repos in temp folders, with global and system git config isolated.

## Acceptance criteria

- `cargo test -p shell` passes on Linux:
  - unit and property tests for version parsing, argv building, progress parsing (splitting stderr into chunks at any point gives the same events) and stderr classification
  - integration tests on temp repos: commit succeeds; a stale expected head or index is refused with the repo unchanged; a held `index.lock` is refused with the lock untouched; "nothing to commit" is classified as `Expected`; cancel during a slow pre-commit hook reports `Cancelled`, kills the hook's grandchild and leaves `HEAD` unchanged
- Each new test is shown to fail once against a planted bug.
- `cargo check --target x86_64-pc-windows-msvc -p shell` passes on the VPS, so the job-object code at least type-checks. CI's Windows job runs the tests for real.
- `cargo xtask check` passes.
