# Task 009 handoff

Backlog task 9: Syntax highlighting layer on tree-sitter.

## What changed

Branch `task-009-highlight`, from `origin/main`.

- **New crate `crates/highlight`** (pure, no IO). Dependencies: `tokens` (in repo), `tree-sitter` 0.27.2 and 15 grammar crates, `proptest` as dev-dependency. One `tree-sitter` version resolves in `Cargo.lock`.
  - `detect(path, linguist_language, first_line) -> Option<Language>`: attribute, then extension (case-insensitive), then shebang (`#!/usr/bin/env -S node` style handled); `.bashrc`-style dotfiles by name.
  - `highlight(language, text, cancel) -> Result<Vec<Span>, HighlightError>`: parses the whole file, runs the cached highlight query, flattens captures into sorted, non-empty, non-overlapping spans on char boundaries (innermost capture wins, later pattern wins ties, adjacent equal spans merge). `cancel` is polled in both parse and query. Over 5 MB or 100k lines gives `TooLarge`.
  - `spans_in(spans, range)` returns the spans touching the visible window by binary search.
  - `Capture` (Keyword, String, Comment, Type, Function, Number) with `token(theme)` and `token_name()`, colours only from `tokens`. Temporary Phase 0 mapping: keyword to accent, string to add-ink, comment to ink-faint, type to lane-2, function to lane-7, number to warning.
- **Grammars shipped (16 languages incl. TSX):** Rust, TypeScript, TSX, JavaScript, Go, Java, Kotlin (`tree-sitter-kotlin-ng`), Python, JSON, YAML, TOML (`tree-sitter-toml-ng`), Markdown (`tree-sitter-md`, block grammar only), HTML, CSS, SQL (`tree-sitter-sequel`), Bash. None left out.
- **Tests:** 7 unit and 15 integration/property tests (22 total in `cargo xtask check`). Property tests: detection order over path/attribute/shebang combos, extension case, detection never panics, span invariants for every grammar over random and fragment-built text (including invalid syntax), `spans_in` equals a filter. One sample per grammar must yield an expected capture.
- **Build time on the 2-vCPU VPS (shared with other agents):** about 41 s for the first `cargo build -p highlight` including all grammar C code, and about 6 s for an incremental test build.

### Planted bugs (all run with `cargo test -p highlight`)

Caught: extension before attribute; shebang before extension; unknown attribute falling through; case-sensitive extension; `env` shebang not followed; ceil and floor not snapping to char boundaries; clamp to text removed; items not sorted; outermost capture wins; earlier pattern wins; no span merge; `spans_in` bounds off by one (both ends); Number token colour changed; token name drift; extra capture name styled; size check removed; line check removed; query cancel ignored; Kotlin query missing `fun`; Bash given the Python query; TypeScript without the JavaScript query; Markdown on the inline grammar.

Survived (equivalent in outcome): **parse cancel ignored.** With a cancel that is always true, the query phase still returns `Cancelled`, so the result is the same; only latency differs. I could not write a test on outcome alone without a phase signal. Left as is.

## What is unfinished

- Windows check: `cargo check -p highlight --all-targets --target x86_64-pc-windows-msvc` cannot run here. `cc-rs` fails with `failed to find tool "lib.exe"` (no MSVC toolchain), so the grammars' C code does not cross-compile. Relying on CI for Windows.
- Not in scope: incremental reparse, styled-line cache, 100 ms timer, Markdown inline and embedded languages.

## Anything surprising

- `tree-sitter-kotlin-ng` ships no highlight query, so `grammar.rs` carries a small own Kotlin query (keywords, strings, numbers, comments). It is guarded by the Kotlin sample tests.
- `tree-sitter-typescript` only ships additions to the JavaScript query, so TS and TSX use both concatenated.
- Query capture names in the grammar crates are not uniform; `Capture::from_name` maps by the first dotted segment and leaves everything else unstyled.

## Spec questions and proposed answers

1. `docs/design/README.md` defines no syntax colours. Used the Phase 0 temporary mapping. Proposed: keep it until a design pass adds real tokens (for example `syntax-keyword`), then change only `theme.rs`.
2. A `linguist-language` value with no shipped grammar (for example `Ruby`) gives plain text and does not fall through to the extension. Spec says "no match, plain text" but is silent on this. Proposed: keep, since the attribute is an explicit user override.
3. The "too large" threshold reuses the diff-engine numbers (5 MB, 100k lines). Proposed: keep them in sync with the diff crate's constants when the viewer wires both.
4. Markdown highlights block structure only (headings, fences, list markers).
