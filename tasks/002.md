# Task 002

## Goal

Create the `tokens` crate: Rust consts for colours (dark and light), type styles, spacing, radii, shadows and fixed sizes, generated from `docs/design/tokens.json`, so the UI never hard-codes them. This is the `tokens` half of the task only.

## Backlog task number

2 in [the plan](../docs/PLAN.md#v01-backlog): "Design tokens crate and component layer skeleton over GPUI". The component layer waits for the Phase 0 gate ("Early start" in the plan), so the row becomes "Core done".

## Files likely touched

- `Cargo.toml` (workspace member)
- `crates/tokens/**` (new: `Cargo.toml`, `build.rs`, `src/lib.rs`, `support/json.rs`, `tests/tokens.rs`)
- `docs/PLAN.md` (row 2 status)

## PRD law numbers

None. The crate backs architecture rule 7 (colours, sizes and spacing come from `tokens`) and the PRD requirements for light and dark themes from the same tokens.

## Constraints

- No GPUI dependency and no runtime dependencies. Colours are plain `Rgba` values.
- No `serde`: it is not in the PRD build-vs-library table. A small std-only JSON reader is used instead. `proptest` is a dev-dependency only.
- The consts are generated by `build.rs` on every build, so they cannot drift from the JSON. A malformed token fails the build with its name.
- Tests do not touch any repository.

## Acceptance criteria

- Every token in `tokens.json` is present in Rust with the same value, in both themes.
- Light and dark define the same keys; dark comes first and is the default.
- Measurable README rules are tests: text and control contrast, diff colour readability, lane contrast and distinctness, the 4px spacing grid, the minimum font size, and `code` line height equal to `row-diff`.
- Each test is shown to fail on a planted bug. The results are in DONE.md.
- `cargo xtask check` passes.

## Out of scope

- The GPUI component layer skeleton (waits for the Phase 0 gate).
- Converting `Rgba` to GPUI colours, and loading or bundling fonts.
- Motion (the README says it is not a token family yet) and icons.
