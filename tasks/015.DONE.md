# Task 015 handoff

Backlog task 15: Branches (create, switch, rename, delete, detached HEAD), **core half only**. Branch `task-015-branches`, from `origin/main` at `0dcfb0b`. The UI half is unfinished and waits for the Phase 0 gate; row 15 in `docs/PLAN.md` is now "Core done".

## What changed

- **Core (pure).**
  - `BranchName::parse` (ids.rs): the rules of `git check-ref-format --branch`, a little stricter (no `HEAD`, `@`, leading dash). Parsed in `step` when a request arrives; a bad name is refused at once (`InvalidName(NameProblem)`).
  - New `crates/core/src/branch.rs`: `plan(request, disk, op)` checks a request against the fresh snapshot and builds `(GitArgs, UndoPoint)`. Refusals (`Refusal::Branch(BranchRefusal)`): `InvalidName`, `NoCommitsYet`, `AlreadyExists`, `NameConflict` (`a` vs `a/b`), `NoSuchBranch`, `IsCurrent` (switch to or delete the checked-out branch), `SameName`; and `Refusal::RepoBusy` during a merge, rebase, cherry-pick or revert (PRD "State machines").
  - New events `BranchCreateRequested`, `BranchSwitchRequested`, `BranchRenameRequested`, `BranchDeleteRequested`; `WriteRequest` and `GitArgs` variants `CreateBranch { at: BranchStart::{Head, Commit(oid)}, switch }`, `SwitchBranch`, `RenameBranch`, `DeleteBranch { force }`; new `Action` variants. Leaving a detached HEAD is `CreateBranch { at: Head, switch: true }`.
  - Rule 5: every `GitArgs` carries the ref values it expects, exposed as `GitArgs::expected_refs()` (create: new name absent; switch and delete: branch at `tip`; rename: `from` at `tip`, `to` absent).
  - Undo (task 12 machinery, extended): branch writes take an undo point like commit. `UndoPoint` gains `index_effect` (`Rewrites` or `Untouched`), `UndoEntry` gains `after_head`, `UndoReplay` gains `index_effect` and `head: Option<HeadRestore>` (`Symbolic` / `Branch` / `Detached`). A create, rename or delete leaves the index alone, so undoing it neither checks nor restores the index (staging done since is kept). Undo now compares `HEAD` with where the operation left it (`after_head`), not where it started, and restores `HEAD` first when the operation moved it.
  - `RefsSnapshot.upstreams: BTreeMap<BranchName, Upstream { name, tracking: Tracking::{Gone, Apart { ahead, behind }} }>`.
- **Shell.**
  - `git.rs`: argv through the git CLI: `branch --no-track <name> <oid>`, `switch -c <name> <oid>`, `switch --no-guess <name>`, `branch -m`, `branch -d` / `-D`.
  - `precondition::check_refs`: reads each expected ref fresh through gix; the runner calls it after the head and index check and refuses with `PreconditionChanged`.
  - `classify.rs`: git's refusals for branches (not fully merged, local changes would be overwritten, used by a worktree, not a valid branch point, ...) are `Expected`; "a branch named ... already exists" is `PreconditionChanged`; `is_unmerged_refusal(details)` for the UI's force-delete offer.
  - `undo.rs`: replay moves `HEAD` (symbolic-ref, or `switch`) before restoring refs, after verifying every ref first, and puts `HEAD` back if the ref transaction fails; the saved index tree is read back only for `Rewrites`.
  - `read.rs`: upstream and ahead/behind through gix (`branch_remote_tracking_ref_name`, `rev_walk` with hidden tips).
- **Decision (dirty switch).** The core does not pre-check local changes: it has no overlap information (status is task 11) and git's own check is exact. git refuses before changing anything; the shell classifies it as `Expected`, no undo point is kept, and the UI shows git's message. Test: `switch_over_clashing_local_changes_is_refused_by_git`.
- **Tests.** Core: `crates/core/tests/branch_props.rs` (4: oracle sim with random create/switch/rename/delete/undo/outside changes, delete-current always refused, plans carry the snapshot's values, busy repos refuse), 3 more in `ids.rs`, and `step_props.rs` extended with branch events. Shell: `crates/shell/tests/branches.rs` (29, real git: every operation with undo, law 8 on refs, `HEAD`, index and files; law 9 by comparing every ref before and after; stale expectations; refusals; upstream counts; name rules against `git check-ref-format`), 2 unit tests in `git.rs`, 1 in `classify.rs`.

## Spec questions, with proposed answers

1. **Undo of delete loses config and reflog.** `git branch -D` also deletes the `branch.<name>.*` config section (upstream tracking), and undo recreates only the ref. Proposed: record the section in the undo point (when the UI task needs it) and write it back with `git config`; until then the UI should say tracking is not restored.
2. **Law 8 and the index.** For create, rename and delete the index is not touched and not restored; for switch it is restored from the saved tree as for commit (entries and tree, not the file checksum; see 012.DONE.md). Proposed: write this in the spec's undo section.
3. **Undo and `HEAD`.** Task 12 refused undo when `HEAD` names another branch. Now the check is against the `HEAD` the operation left (`after_head`), and an undo of a switch/rename/create-switch moves `HEAD` back first. The spec's "Replaying an undo" says only refs and index. Proposed: add "and `HEAD` when the operation moved it". A switch undo also rewrites worktree files (it is a checkout), which contradicts "never rewrites working-tree files except to reverse a discard"; proposed: allow it for switch, since the user asked for the files to change.
4. **Ahead/behind cost.** Counts walk history per branch with an upstream, uncapped. On a huge diverged history this can be slow; the read budget is not measured for it. Proposed: benchmark with the 1M-commit fixture in task 24 and cap or move it to a background read if over budget.
5. **Upstream `.`** (a local branch tracking another local branch) and remotes without a fetch refspec are read as "no upstream". Proposed: accept for v0.1.
6. **Case-only rename on Windows** (`main` to `Main`): the core compares names case-sensitively, so it is allowed and left to git. Not tested here (Linux). Proposed: add a Windows-only test when the UI half lands.
7. **Name rules.** Stricter than git: no `HEAD`, `@`, leading `-`. Branch names with non-ASCII characters are accepted (git accepts them).

## Anything surprising

- `git check-ref-format --branch @` succeeds (it expands `@` to `HEAD`), so the git-agreement test treats `@`, `HEAD`, a leading dash and `@{...}` as intentionally stricter.
- git's message for a missing start point is `fatal: not a valid branch point` (create) or `reference is not a tree` (switch -c), not `not a valid object name`.
- A ref transaction cannot delete the branch HEAD is on without leaving HEAD dangling for a moment, so the replay restores `HEAD` first, then the refs.
- Two `.proptest-regressions` files created by planted bugs were removed before committing.
