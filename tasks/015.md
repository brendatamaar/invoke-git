# Task 015

## Goal

Add the core (non-GPUI) half of branch management: create (from `HEAD` or a given commit, optionally switching to it), switch, rename and delete, plus leaving a detached `HEAD` by creating a branch. Every operation goes through the op queue with the ref values it expects, takes an undo point (task 12), and is refused with a stated reason when it cannot run. The refs snapshot also carries each branch's upstream with ahead/behind counts.

## Backlog task number

15 in [the plan](../docs/PLAN.md#v01-backlog): "Branches: create, switch, rename, delete, detached HEAD" (Core + UI, depends on 5). This task is the core half only; the UI half waits for the Phase 0 gate.

## PRD law numbers

- 8: undo restores every ref, `HEAD` and the index for create, switch, rename and delete. Owning tests: `crates/shell/tests/branches.rs` (real git) and the oracle in `crates/core/tests/branch_props.rs`.
- 9: no operation moves a branch the user did not target. Same tests; every run compares all refs before and after.
- 12 and 13 (from task 3): a branch write waits for a fresh snapshot and a free lock, and is followed by a full re-read.
- Rule 5: each run carries the ref values it expects (`GitArgs::expected_refs`) and the shell refuses it when disk differs.

## Constraints

- `core` stays pure, with no new dependencies. All IO is in `shell`: reads through gix, writes through the system git CLI.
- Names typed by the user are parsed in the core (`BranchName::parse`) and never reach argv unless valid; starting points are object ids.
- Phases are enums (`BranchStart`, `HeadRestore`, `IndexEffect`, `Tracking`); no booleans for lifecycle.
- Decision to record: a switch that git would refuse (local changes would be overwritten) is left to git. It refuses before changing anything; the shell classifies it as an expected failure.
- Other agents add variants to the same enums in parallel: keep additions grouped and commented, do not reformat existing code.

## Acceptance criteria

- Create (from `HEAD`, from a commit, with and without switching), switch, rename and delete work through the queue and each can be undone; undo restores refs, `HEAD`, index and files exactly.
- Refused in the core with a reason: invalid name, name exists, name clashes (`a` / `a/b`), no such branch, switching to or deleting the current branch, renaming to the same name, a repo in the middle of a merge or rebase, a branch with no commits yet.
- Delete of an unmerged branch needs `force`; without it git refuses and the failure is classified as expected.
- A stale expected ref value is refused by the shell as `PreconditionChanged` before git runs.
- `RefsSnapshot.upstreams` holds upstream, ahead and behind per branch, and `Gone` when the upstream ref is missing.
- Property tests in core (refusals match an independent oracle, deleting the current branch is always refused, plans carry the snapshot's values, no write on a stale or locked snapshot); integration tests on temp repos; each shown to fail by a planted bug (listed in DONE.md).
- `cargo xtask check` passes.

## Out of scope

- The UI half (branch list, dialogs, ahead/behind display), which waits for the Phase 0 gate.
- Entering a detached `HEAD` (`switch --detach`), set upstream, fetch and push (task 17), tags.
- Restoring a deleted branch's `branch.<name>.*` config on undo.
