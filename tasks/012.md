# Task 012

## Goal

Add the undo system: before each write the core asks the shell to save the index as a tree object and records the refs the write may move; `UndoRequested` replays that record (refs through `git update-ref` with the expected value, index through `git read-tree`), and refuses with a stated reason when anything else moved the repo since.

12 in [the plan](../docs/PLAN.md#v01-backlog): "Undo system: reflog and index snapshots" (depends on 5).

## PRD law numbers

- 8: undo restores every ref and the index to their exact previous values. Owning test: `crates/shell/tests/undo.rs` (real git), plus the oracle property in `crates/core/tests/undo_props.rs`.
- 9: no operation moves a branch the user did not target. A replay touches only the refs recorded in the undo point.
- 12 and 13 (from task 3): an undo is a write in the op queue, so it waits for a fresh snapshot and a free lock, and is followed by a full re-read.

## Constraints

- `core` stays pure and gets no new dependencies. All IO is in `shell`, through the system git CLI (`write-tree`, `update-ref`, `read-tree`).
- Every write carries what it expects (rule 5): each restored ref carries its current value, and the replay carries head and index.
- Phases are enums (`UndoPending`, `Reversible`); no booleans for lifecycle.
- The stack is in memory, bounded at 50. SQLite persistence is not added (SQLite is not in the PRD's build-vs-library table); see DONE.md.
- Discard restore (writing saved blobs back to paths) is task 13. This task leaves a marked hook in `UndoPoint` and `UndoReplay`.

## Acceptance criteria

- `UndoRequested` is refused with a stated reason when the stack is empty, the top point is not undoable (a push), a merge/rebase is in progress, or the head, a recorded ref or the index moved since the operation.
- Otherwise the undo is queued like any write and replays only the recorded refs.
- Property tests in core: stack bound, refusal reasons, no undo write on a stale or locked snapshot, core agrees with an independent oracle over random commit/undo/outside-change sequences.
- Integration tests on temp repos: undo of commit and of amend restores HEAD, branch and the index exactly (law 8); no other ref moves (law 9); undo refused after an outside commit, an outside index change and a branch switch; a failed snapshot or stale replay changes nothing.
- Each new test is shown to fail by a planted bug (listed in DONE.md).
- `cargo xtask check` passes.

## Out of scope

- SQLite persistence across restarts.
- Discard restore (task 13), push (task 17), redo.
- Wiring into the app loop (the shell functions are ready to call).
