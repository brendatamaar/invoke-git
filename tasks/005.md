# Task 005

## Goal

Read a repo's state from disk, as the spec's ordered rules describe:

- discover a repo from any path inside it, including linked worktrees and `.git` files, and refuse bare repos with a clear error
- decide the phase (`Clean`, `Merging`, `Rebasing`, `CherryPicking`, `Reverting`) from the in-progress markers in the worktree's own git dir, with the rebase step and total parsed from marker files
- read head, conflicts (index stages 1-3), all refs with ids, the index id and the lock into one `DiskState`
- run `Command::ReadState` and report it as `Event::StateRead` or `Event::ReadFailed`

## PRD law numbers

- 11: the state always equals what is derived from `.git` on disk. This task is the "derived from disk" half: one function reads everything fresh, and the core only ever replaces its snapshot with the result. The owning model-based test comes with task 24.

## Constraints

- The detection rules and the marker-file parsing are pure and live in `core`. The shell only reads files and gix, and builds the description the pure function takes.
- Reads go through gix. No git CLI.
- The rebase markers live in the worktree's own git dir, not the common dir.
- `read_state` and the write check share `precondition::index_id`, so snapshot and check agree.
- No new dependencies. gix gets its `index` feature (needed to read index stages), which is part of the same crate.
- Tests use generated temp repos with system and global config shut out.

## Acceptance criteria

- Property tests: counter parsing never panics and round-trips, the rule order holds for every combination of markers, conflicts pass through unchanged.
- Integration tests on temp repos: clean, merging with a real conflict, stopped rebase (step and total), cherry-pick and revert with conflicts, detached HEAD, unborn branch, linked worktree, `.git` as a file, held `index.lock`, packed refs, discovery from a subdirectory, bare repo refused.
- Each new test is shown to fail against a planted bug.
- `cargo xtask check` and the Windows-target check and clippy pass.

## Out of scope

- `StatusSnapshot` (task 11, left empty), upstream and ahead/behind (task 15), the watcher (6).
- Telling our own `index.lock` from someone else's (`HeldByUs`): any `index.lock` is `HeldByOther`.
