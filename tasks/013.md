# Task 013

## Goal

The core (non-GPUI) half of "Discard file, hunk or lines, undoable":

- pure patch building: `diff::build_patch` gets a third direction, `Discard` (diff is index to worktree, the patch applies to the worktree text and turns each selected line back into the index's)
- core handling: a discard goes through the op queue (fresh snapshot, free lock, clean phase, expected index id, expected file bytes, undo point)
- shell execution: `ApplyPatchToWorktree` saves the pre-discard content as a blob (kept alive under `refs/invoke-git/undo/<op>-discard`), then runs `git apply` on the worktree; undo writes the saved content back to its path and mode
- the laws registry and the model-based harness learn about discard (law 7 gets its owning test)

13 in [the plan](../docs/PLAN.md#v01-backlog): "Discard file, hunk or lines, undoable" (Core + UI). This task is the core half. The discard UI waits for the Phase 0 gate, so row 13 becomes "Core done".

## PRD law numbers

- 7: discarding a selection changes only the selected lines (owner: `law_7_discard_changes_only_selected_lines`, proptest on real repos, diff + shell)
- 8: undo restores the exact bytes of a discarded file (the discard part of law 8)
- Also rule 4 (disk is the truth), rule 5 (every write carries what it expects: `based_on` and `expect_file`) and law 12 (waits for `index.lock`).

## Constraints

- `diff` and `core` stay pure. Patch building is a function of a `TextDiff` and a selection.
- Writes go through the system git CLI (`git apply`, `hash-object -w`, `update-index`, `write-tree`, `update-ref`); reads through gix. The only direct file writes are the undo's (the spec: "write the saved blobs back to their paths").
- No new dependencies.
- The UI half is not built: no `ui` or `app` changes.

## Acceptance criteria

- Pure proptests: a discard patch applied to the worktree text gives exactly the text with only the selected changes reverted (CRLF and end-of-file marker included); discarding everything gives the index text; header counts match.
- Core tests: a discard runs only on a fresh snapshot, with a free lock, a clean phase and an index equal to `based_on`; it takes an undo point; a running discard is not cancelled; its undo plan touches no ref and not the index.
- Integration tests on temp repos (CRLF, no final newline, unicode and spaced paths, untracked, deleted and empty files, executable mode, binary refused with a reason, stale index refused, edited file refused, merge in progress refused, path outside the repo refused): law 7 against real git; undo restores the exact bytes; undo refuses over a file changed since.
- The harness generates discards and compares app and twin after every step.
- Each new test is shown to fail once by planting a bug (listed in the DONE file).
- `cargo xtask check` passes.

## Out of scope

- Any UI (discard buttons, confirmation dialog): the other half of task 13.
- Binary, symlink, submodule and mode-only discards (they need `git checkout`/`git rm`, not a text patch).
- Discarding several files in one operation (one request is one file; "discard all" is one request per file).
- Persisting undo points across restarts (task 12's open question).
