# Task 017

## Goal

The core (non-GPUI) half of fetch, pull, push and set-upstream:

- core: real handling for `PushRequested` (replacing the `NotYetSupported` refusal) and new `FetchRequested`, `PullRequested` (merge or rebase) and `SetUpstreamRequested`, all through the op queue with progress, cancel and in-app auth. Force push is only ever `--force-with-lease=<ref>:<expected oid>`, with the oid taken from the snapshot's remote-tracking value (the value the user reviewed); a force without a known remote value is refused.
- shell: argv building for the four operations, askpass wiring for network ops (reusing task 16's `AskpassServer`), and classification of outcomes (a rejected push, including a stale lease, is `Expected`).

## Backlog task number

17 in [the plan](../docs/PLAN.md#v01-backlog): "Fetch, pull (merge or rebase), push with `--force-with-lease`, set upstream". This is the core half; the fetch/pull/push controls and the rejected-push prompt (UI) wait for the Phase 0 gate.

## PRD law numbers

- 9: fetch moves remote-tracking refs only; never a local branch.
- 10: no force push without `--force-with-lease=<ref>:<expected>`; the expected value is the reviewed remote value.
- 13: cancel kills the whole process tree, reports `Cancelled`, and the repo is as it was.
- 12: network writes wait in the op queue like every other write.
- Quint spec 2 invariants: fetch never moves a local branch; push leases against the reviewed value.

## Constraints

- `core` stays pure: no IO. Argv building lives in `shell` (typed `GitArgs` in the core).
- Network through the system git CLI; no gix for fetch, pull or push.
- Reuse task 16's askpass server and the runner's `run_child`; do not duplicate them.
- No new dependencies.
- Tests use temp folders and local bare remotes (plus the throwaway `127.0.0.1` 401 server for auth); never the user's repos.

## Acceptance criteria

- Unit and property tests on argv building: no code path builds `--force` or a lease without its expected value.
- Core tests: force push leases the snapshot value; force without a known value is refused; pull is refused during a merge or rebase; a rejected push is `PushRejected`; push and pull leave an irreversible undo marker; fetch and set-upstream take none.
- Integration tests with a local bare remote: fetch moves only remote-tracking refs, push, set upstream via push, rejected push is `Expected`, force-with-lease refused when the remote moved since review, pull merge, pull rebase, pull conflict is `Expected`, set-upstream, cancel mid-fetch leaves the repo unchanged, stale precondition refused.
- Fetch and push prompt for credentials in-app against a 401 server and end as `Failed(Auth)`.
- Each new test fails once against a planted bug.
- `cargo xtask check` passes.
