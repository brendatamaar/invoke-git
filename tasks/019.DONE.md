# Task 019 handoff

Backlog task 19, "Commit detail view with its diff" (UI). Row 19 in `docs/PLAN.md` is now "Done (Windows checklist pending)".

## What changed

- **`shell::commit_detail`** (new, reads through gix): `read_commit(paths, id)` gives the full message, author and email, author time and offset, parent ids and the changed files against the first parent (the empty tree for a root commit), sorted by path, folders not listed, renames switched off. `read_commit_sides(paths, id, path)` reads the text of the file in the commit and in its first parent; binary, non-UTF-8, symlink and submodule sides come back as `InputsError::NotText` with the reason. `staging::text_of` and `Side` became `pub(crate)` for it.
- **`ui::commit_detail`**: `CommitDetail` (header with subject and a scrollable body, facts: Commit, Author, Date, Parent(s), a `FILES CHANGED · n` list of up to 7 rows and then a scrollbar, Copy hash, and the diff passed in as a child), plus the pure helpers `split_message` and `short_hash`. `ui::time::format_date_time(seconds, offset)` prints `2024-03-05 10:20 +07:00` (the author's own time).
- **`app::commit_pane`**: `CommitPane` with a phase enum (`Nothing`, `Loading`, `Ready`, `Failed`). Selecting a graph row (`GraphEvent::Selected`) shows the commit; the first file is chosen and diffed by itself; choosing another file reloads the diff; syntax colours follow when the parse is done. Copy hash writes the full id to the clipboard.
- `HistoryPane` now renders the graph and the 520 px detail column side by side; `RepoView` shows the `HistoryPane`.

## What is unfinished

- No per-file `+n −m` counts in the list (the mockup has them): they need both sides of every file read, which is too much for a commit with hundreds of files. Proposed: read them lazily for the rows on screen, or count them in the shell.
- No "Not on origin/main yet" line and no "Open full diff" button (the diff is already shown below). A merge is shown against its first parent only.
- Rename detection is off: a moved file is one delete and one add.
- The detail column has a fixed width (520 px); it does not shrink with a very narrow window.
- The commit message body is plain text, not selectable.

## Spec questions (proposed answers)

1. **Merge diff.** The PRD says only "commit detail with diff". Decision: first parent, with a label. Proposed: keep for v0.1, add a "combined" or "against parent 2" switch later.
2. **Date.** Shown in the author's offset, not the viewer's time zone (no tz database in the PRD table). Proposed: keep; `git log` prints it the same way.
3. **Counts per file** (see above) cost time: proposed to measure with the task 24 benchmarks before adding them.

## Anything surprising

- First draft: "Copy hash" was centred over the whole width and the file rows were only as wide as their text; fixed with `w_full()` on the rows and a flex row around the button.
- gix's tree diff, with rewrites turned off, did not need the folder filter in my fixtures, but the code keeps it (planted bug S3 shows the tests notice when it is gone).

## I ran it on this laptop

A fixture repo (merges, branches, a tag, a commit touching 11 files with a two-paragraph body): History page, clicked a commit: the right column shows the subject, body, facts and the file list with the first file's diff; clicking another file swapped the diff; a merge shows two parents and `against the first parent`; a commit with one added file shows `A` and the added line in green.

## Windows checklist (tasks 2, 7, 10, 11, 14, 15, 18 apply too)

`cargo run --release -p app -- C:\path\to\a\throwaway\repo`, open **History**.

1. Click a commit: the right column fills in (subject, body, Commit, Author, Date with the author's offset, Parent). `git show --stat <hash>` lists the same files; `git show -s --format=%ad --date=iso <hash>` matches the date.
2. The first file is shown at once; click another file in the list and the diff changes, with the syntax colours following a moment later.
3. A merge commit shows two parents and `against the first parent`; `git diff <hash>^1 <hash> --name-status` matches the list.
4. The root commit lists everything as `A`. An empty commit (`git commit --allow-empty`) says `This commit changes no file.`
5. A binary file (a PNG) in a commit: the diff area says it is binary and there is no text diff.
6. A commit with more than 7 files: the list scrolls with its own scrollbar; the diff stays visible below it.
7. Copy hash, then paste in Notepad: the full 40 characters.
8. Click quickly through many commits: an older commit's diff never replaces a newer one's.
9. Press F5 or commit something while a commit is shown: the panel keeps showing that commit.
10. At 150% and 200% scale the column is not clipped and the diff's Split/Unified switch is reachable.
