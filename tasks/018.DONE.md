Backlog task 18, lane layout and paging half only: "Commit graph: lane layout, paging, renderer". Row 18 in `docs/PLAN.md` is now "Core done".

## What changed

Branch `task-018-graph-layout`, from `origin/main`.

- **New crate `crates/graph`** (package `graph`), pure, no runtime dependencies. `proptest` is a dev-dependency only. No dependency on `core`, `gix` or the spike crates; the layout is generic over the commit id (`Copy + Eq`).
- `Layout<I>`: `push_page(&[Commit<I>])` (or `place` per commit) appends one `Row` per commit. The open-lane state lives in the layout, so the next page continues without recomputing (spec: "saves its lane state at the page edge"). `PAGE_SIZE = 5000` is exported for the shell.
- `Commit { id, parents, truncated }`: children first, first parent first. `truncated` marks a shallow-boundary commit: parents are ignored, the lane ends and the row is flagged for the faded stub.
- `Row` (16 bytes): column, colour index (0..8), merge flag, truncated flag, offset and counts into a shared edge arena, and width. Row `i` is the `i`-th commit pushed. Edges (`Edge { column, color }`, 4 bytes): arriving edges (every lane that waited for the commit, own lane included) then leaving edges in parent order.
- Lanes keep their column for life, so pass-through lanes are straight. They are not stored per row: `lanes_before(i)` and `passing(i)` rebuild them from a checkpoint (open lanes every 128 rows) plus at most 127 replayed rows.
- Colour: a lane gets the next palette colour (rotation of 8) when it opens and keeps it; the dot takes the colour of its leftmost arriving lane.
- **Tests** (`crates/graph/tests/layout_props.rs`, 5 proptests with 128 cases over random DAGs with parents outside the pages and shallow tips, plus 4 edge-case unit tests and one ignored timing test):
  - `edges_point_down_to_the_parent` (law 14): one row per commit, every leaving edge reaches its parent's row below, no dot sits on a lane that waits, the lane is in `passing` for each row between, colour kept, missing parents keep their lane to the bottom.
  - `paging_does_not_change_the_layout`: any page size gives identical rows, edges, lanes and checkpoints.
  - `replayed_lanes_match_the_live_lanes`: checkpoint replay agrees with the live lanes.
  - `waited_parents_stay_waited_for`: the Kani target "lane placement step" as a proptest; also step 4 joins an existing lane.
  - `dot_colour_follows_its_lane`: leftmost arriving lane, colour in range, width covers edges.

- **Timing** (release, VPS, `cargo test -p graph --release -- --ignored --nocapture`): 100k commits with a branch forking and merging every 10 commits: layout 22 ms; 100 `passing()` lookups 0.12 ms. This history keeps only a few lanes open. Cost is O(open lanes) per commit (linear scans), so a kernel-like history with hundreds of lanes is slower; criterion benchmarks on fixture repos belong to task 25.

## Anything surprising

- Spec questions with proposed answers:
  1. **Input order is trusted.** A parent arriving before its child, or a duplicate id, is not detected (that needs a set of placed ids, about 32 MB per million commits). Proposed: the shell's topo walk guarantees order and uniqueness; keep it out of the layout.
  2. **Arriving edge for the own lane.** The spec says only the other lanes "draw an edge into c's column". Here the own lane is also an arriving edge (straight), so the renderer knows whether to draw the top half (branch tips have none). Proposed: note it in the spec.
  3. **Shallow clones.** Spec says "parents beyond the boundary are missing". Here the shell sets `Commit.truncated` for boundary commits. A parent that is merely missing (not flagged) keeps its lane open to the bottom. Proposed: update the spec to name the flag.
  4. **Lane count above 65,535** saturates the column at `u16::MAX`; the spec's row record uses `u16`, so this is the stated limit.
  5. Edge colour for a joined lane is the target lane's colour; for a new lane, the next rotation colour.
- Property tests take about 15 s in debug because `passing()` is checked for every row between an edge's ends.
