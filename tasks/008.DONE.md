# Task 008 handoff

Backlog task 8: Diff engine: Myers + histogram, hunks, word-level diff.

## What changed

Branch `task-008-diff-engine`, from `origin/main`.

- **New crate `crates/diff`** (package and library `diff`; no clash with anything in the workspace). It is pure, has no runtime dependencies, and `proptest` is a dev-dependency.
  - `diff_text(old, new, &DiffOptions) -> TextDiff`. Inputs may be `&str`, `String` or `Arc<str>`.
  - `myers.rs`: linear-space Myers (middle snake), minimal edit script. `histogram.rs`: git-style histogram (rarest line, longest run, 64-occurrence chain limit), with Myers inside regions that have no anchor. Anchoring uses a work list, not recursion, so a long chain of anchors cannot overflow the stack.
  - Preprocessing: lines are split keeping their endings and interned to `u32` ids; lines that occur on only one side are flagged changed up front and left out of the real diff (as git's record cleanup does); common prefix and suffix are stripped in each region.
  - `slide.rs`: post-processing that slides each changed group to a block edge (simplified indent heuristic, see Q3).
  - `hunks.rs`: changes become hunks with context (default 3), git-style headers (`old_start` is the previous line when `old_len` is 0). `TextDiff::hunks_with_context(n)` widens context without recomputing.
  - `apply.rs`: `TextDiff::apply(a) -> Result<String, ApplyError>`. It checks removed lines against `a` byte for byte and fails on a diff that does not fit.
  - `word.rs`: `word_diff(old, new)` (tokens, Myers on token ids, 30% rule, merge across one whitespace token) and `TextDiff::fill_inline(hunk)`, which pairs removed and added lines by position inside each block and fills `DiffLine::inline`.
  - Options: histogram or Myers, whitespace modes (exact, ignore change, ignore all) applied at interning, ignore blank-line-only hunks, context, indent heuristic, and `max_work` (a work counter, since the crate has no clock). When it runs out the result is one whole-file replace hunk and `note = Some(DiffNote::TooExpensive)`.
  - Data model follows the spec: `Hunk`, `DiffLine` (kind, old/new number, `TextRange` into the shared buffers, `Eol::{Lf, CrLf, None}`, lazy `inline`), `Stats`. `FileDiff` and its kinds are not here (see unfinished).
- **Tests** (`crates/diff/tests`, 23 tests, all pass):
  - `laws.rs` has proptests (1000 cases each) for law 1, law 2 and law 3, over random texts built from a pool with many repeats, CRLF and LF mixed, blank lines, unicode, and a random missing final newline; both algorithms, context 0 to 5, indent heuristic on and off. Also: Myers is minimal against an LCS oracle, histogram is never smaller than minimal, a run out of budget is still law 1 and law 3 correct, and word spans are valid and leave the same non-whitespace text outside.
  - `examples.rs` has 16 worked cases: headers, hunk merging at exactly 6 and 7 lines, EOF and CRLF handling, empty texts, options, histogram anchoring, sliding, too-expensive, word diff, `fill_inline`, and the speed check.
- **Speed.** `big_file_with_many_changes_is_fast` diffs 50k lines with about 6k changed lines (2k replaced, 2k deleted, 2k inserted; a third of the lines are braces and other common lines) and applies the result. It asserts under 10 s in debug and 2 s in release, which only catches a complexity blowup. Measured in release on this shared VPS: about 80 ms alone (up to 250 ms while other agents were building). That is the diff only, not the viewer. Real benchmarks are task 25.
  - Finding: the first version took 70 s on this input and tripped the budget. Anchoring on the longest run rescanned the whole remainder once per change. Two fixes: lines unique to one side are removed before diffing, and ties between equal-length anchors go to the one nearest the middle of the region.

## Anything surprising

- The spec's own word-diff example, `foo bar` to `baz qux`, is skipped by its rule 2: the only shared token is one space, 1 of 7 bytes, under 30%. The tests pin this behaviour.
- A line's identity includes its ending, so `a\r\n` and `a\n` are different lines, and `b` with no final newline differs from `b\n`. This matches git, and means a CRLF/LF conversion shows every line changed.
- With whitespace-ignoring options, context lines show the new side's text and ending, and `apply` copies them from the old text, so `apply == new` is only promised for exact comparison (laws are stated for that).

## Spec questions (proposed answers)

1. **Text type.** `diff_text` takes `&str`, so a non-UTF-8 file needs lossy conversion first, which would break byte-exact staging. **Proposed:** task 11 decides; either diff `&[u8]` (word diff stays on valid UTF-8 lines) or treat non-UTF-8 as "binary" in the classification. I did not add a dependency or guess.
2. **`TextDiff` owns both buffers (`Arc<str>`).** The spec shows `text: TextRange` into shared buffers, but `apply` needs the added text too, so the diff carries both buffers; `Removed` lines point into the old buffer and all others into the new one. **Proposed:** update the spec's data model section to say so.
3. **Indent heuristic is simplified.** Git's scoring is not reproduced; the engine slides a group up to 100 lines either way and scores positions (starts after a blank line, ends on or before a blank line, does not end before a deeper line). **Proposed:** accept for v0.1 and tune on real diffs in the viewer.
4. **Word diff rule 2** (above). **Proposed:** keep the rule but count only non-whitespace shared bytes against the longer line's non-whitespace bytes, or lower the threshold; change the spec example instead if the rule stays as written.
5. **Budget unit.** `max_work` is roughly one unit per line compared; default 50 million. **Proposed:** task 25 calibrates it to 200 ms on the reference laptop.
