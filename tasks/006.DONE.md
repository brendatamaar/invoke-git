# Task 006 handoff

Backlog task 6: file watcher with debounce, emitting refresh events.

## What changed

- `crates/core/src/watch.rs` (pure): `WatchRoots::classify` maps an absolute path to an `Area` (or none) relative to the worktree, the worktree's own git dir and the common dir. `Debounce` coalesces with a 50 ms quiet period; time is passed in. Proptests cover the three debounce properties against a reference model, `objects/` never classifying, case/separator independence on Windows roots, and worktree paths.
- `crates/shell/src/watch.rs`: `RepoWatcher::start(&Discovered, Sender<Event>)`. `notify` watches the worktree recursively (and the git dirs separately only if outside it). A thread feeds the debouncer from `Instant` and sends `Event::DiskChanged`. Ignore rules come from gix (`.gitignore` files, `info/exclude`, user excludes), reloaded for every burst. `Access` events are skipped. An OS overflow or watch error reads as "all areas", so a lost event cannot hide a change. Dropping the watcher stops and joins the thread.
- Dependency: `notify` 8 (in the PRD table); gix gets its `excludes` feature.
- Classification: `HEAD` is Head; `index` and `index.lock` are Index; `refs/` and `packed-refs` are Refs; `MERGE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `rebase-merge/`, `rebase-apply/` are InProgress; other worktree paths outside `.git` are Worktree. Everything else (`objects/`, `logs/`, `FETCH_HEAD`, `config`) is none.
- Checks: `cargo test -p invoke-core watch`, `cargo test -p shell --test watch`, Windows-target clippy, `cargo xtask check`.

### Planted bugs (all caught)

Emit before quiet; timer never restarts; pending not cleared after emit; case folding skipped; `objects/` classified as Refs; union keeps only the first area (all by core proptests); ignore rules skipped; all events dropped; removing the `Access` filter (shell integration tests). One attempt (checking only the last path component for ignores) survived, which showed gix's stack already treats paths inside an ignored folder as ignored, so I removed my redundant per-ancestor loop.

## What is unfinished

- Nothing in scope. The read is not yet narrowed in the shell: `ReadScope` is advisory (task 5 design).

## Anything surprising

- A plain commit on a branch does not touch `.git/HEAD`; it reports Refs and Index (via `index.lock` and `index`). Head fires on a branch switch.
- Tracked files that match an ignore rule (added with `-f`) are treated as ignored, so edits to them do not fire. Git itself still tracks them.

## Spec questions

1. **Tracked-but-ignored files.** Edits to them are not reported. **Proposed:** accept for now; if it matters, check the index for the path before ignoring it.
2. **Case-insensitivity on macOS.** I treat macOS as case-insensitive (default volumes), though APFS can be case-sensitive. **Proposed:** accept; classification only affects git-dir names, which are lowercase anyway.
3. **Recursive watch of `.git/objects`.** inotify holds watches for those folders even though events are dropped. **Proposed:** accept; revisit only if a huge repo shows watch exhaustion (then watch git-dir files non-recursively).
4. **Extra event at lock release.** `index.lock` creation counts as Index so `LockState` stays fresh; a commit may therefore produce a second event just after the first if git takes longer than 50 ms between steps. Harmless; reads are idempotent.
