# Task 010

## Goal

The diff viewer: split and unified layouts of one file's diff in a virtualized list, with line numbers, add and remove colours, syntax colours and word-level change marks, plus a flat list of changed files to pick the file (the status tree of task 11 replaces the list).

## Backlog task number

10 in [the plan](../docs/PLAN.md#v01-backlog): "Diff viewer: split and unified, virtualized". Depends on 2 (components), 8 (diff engine) and 9 (highlighting).

## Files likely touched

- `crates/ui/src/{code_text,diff_rows,diff_view,scrollbar,changes}.rs`, `crates/ui/src/components/segmented.rs`, `crates/ui/src/{summary,text,lib}.rs`, `crates/ui/examples/diff.rs`, `crates/ui/Cargo.toml` (depends on `diff` and `highlight`)
- `crates/app/src/{repo_view,diff_load,workspace,main}.rs`
- `docs/PLAN.md` (row 10), `tasks/010.DONE.md`

## PRD law numbers

None directly (the viewer only reads). It carries the Phase 0 gate findings: rows are fixed height (`row-diff`, so a `uniform_list`), and dragging the scrollbar must never show rows without their colours.

## Constraints

- Rule 7: the viewer renders what it is given and sends nothing back. Colours, sizes and text styles come from `tokens`. The diff and the highlight are computed by the caller off the UI thread.
- Layout (rows from a diff) is pure and property tested; so are the line styling merge and the scrollbar geometry.
- No new dependencies. `ui` now depends on `diff` and `highlight` (the crate diagram already says so).
- Windows: CRLF files (with `core.autocrlf=true`) show only their real edits (see task 011 follow-up).

## Acceptance criteria

- Split and unified show every changed line once, with old and new line numbers, `+` and `−` signs (so colour is never the only signal), add and remove backgrounds, syntax colours, word-level marks, and the hunk headers.
- A drag of the scrollbar from top to bottom through the 50k-line fixture shows every row coloured at once: syntax spans cover the whole file, so no row waits for a highlight.
- Tabs, a missing final newline, long lines, deleted and new files, binary files and "diff too expensive" all show something sensible.
- The open diff refreshes when the file or the index changes (task 011, question 5), keeping the scroll position.
- Tests fail on planted bugs. `cargo xtask check` passes. The UI half ends with a Windows checklist in DONE.md.

## Out of scope

- Staging, unstaging and discard controls, line checkboxes, hunk action buttons (task 11); the status tree (task 11); the commit detail diff (task 19); the pre-push review (task 21).
- Ignore-whitespace (needs the diff recomputed), text selection and copy, horizontal scroll, image preview.
- Benchmarks for the viewer (task 25, the rest).
