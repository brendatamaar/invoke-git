# Task 020

## Goal

Add stash to the core and the shell: save (with or without untracked files), apply, pop and drop. Each request names a stash by its commit id and is refused when that stash is no longer where the core read it. The UI half waits for the Phase 0 gate and is not part of this task.

## Backlog task number

20 in [the plan](../docs/PLAN.md#v01-backlog): "Stash: save (incl. untracked), apply, pop, drop" (Core + UI; depends on 5). This task is the core half only.

## PRD law numbers

- 8: undo restores refs and the index exactly. A drop of the newest stash is undone by storing it back; every other stash operation says why it cannot be undone.
- 9: no operation moves a branch the user did not target. A stash never moves a branch or `HEAD`; tests compare every ref before and after.
- 13: a cancelled operation leaves the repo unchanged or in git's own state. `git stash` is not atomic, so a running stash operation is not cancellable.
- 12 (from task 3): stash writes wait for a fresh snapshot and a free lock.

## Constraints

- `core` stays pure and gets no dependencies. The stash list is read in `shell` through gix (the reflog of `refs/stash`), never through `git stash list`.
- Writes go through the system git CLI (`stash push`, `apply`, `pop`, `drop`, `store`).
- Every write carries what it expects (rule 5): a stash is addressed by commit id, the core plans the position from the fresh snapshot, and the shell re-reads the list just before running and refuses if the entry at that position has another id.
- A pop or apply that conflicts is an expected outcome (`ErrorClass::Expected`); git keeps the stash and leaves its own conflict state.
- Phases are enums (`Reversal`, `Irreversible`); no booleans for lifecycle.
- No new dependencies.

## Acceptance criteria

- Core: stash requests are queued like any write, planned at dispatch against the fresh snapshot, and refused with a stated reason (`StashGone`, `RepoBusy`) before anything is written.
- Property tests in core: found by id or refused, no write on a stale or locked snapshot, busy repos, message cleaning, drop undo, not-undoable reasons, a conflicted pop records nothing, no cancel of a running stash op.
- Integration tests on temp repos: save with untracked files; save without; nothing to save; apply; pop; pop by id after another stash landed; pop with a conflict (stash kept, repo in git's own state); apply over local changes; drop and its undo; drop of an older stash (not undoable, commit kept); a stale stash id refused by the core and by the shell; law 9 on every operation.
- Each new test is shown to fail by a planted bug (listed in DONE.md).
- `cargo xtask check` passes.

## Out of scope

- The stash UI (list, buttons, confirmation of drop): the UI half of task 20.
- Stash of a single path or hunk, `--keep-index`, branch-from-stash.
- Wiring into an app loop.
