# Technical Decisions

| Tanggal | Keputusan | Alasan | Fase |
|---------|-----------|--------|------|
| 2026-11-20 | Pin GPUI ke Zed tag `v1.29.2` (`2de9e435...`) + mirror patch `async-task` | Release stabil yang teruji di Windows (Win32/DX11/DirectWrite); hindari breakage dari `main` GPUI | P0 |
| 2026-11-20 | Hybrid git engine: `gix` untuk baca, system `git` CLI (≥ 2.40) untuk tulis & jaringan | `gix` cepat & bebas lock untuk status/log/diff, sedangkan CLI menjamin kompatibilitas penuh hooks, kredensial, push, merge, rebase | P1 |
| 2026-11-20 | Pure core (`step(state, event) -> (state, commands)`) + semua IO di `shell`, disk `.git` sebagai source of truth | Memungkinkan property testing (`proptest`) & model-based harness tanpa IO, serta tahan perubahan eksternal dari terminal/IDE | P1 |
| 2026-11-20 | Setiap operasi tulis membawa expected state (`index` id / ref value) & menolak saat `index.lock` aktif | Menegakkan Law 11 & 12 agar tidak pernah menimpa perubahan disk diam-diam | P1 |
| 2026-11-21 | Generator token desain sendiri (`crates/tokens/build.rs` dari `docs/design/tokens.json`) + komponen UI tipis di atas GPUI | Mengisolasi API GPUI pre-1.0 dan memastikan light/dark theme konsisten tanpa nilai warna hard-coded | P1 |
| 2026-11-22 | Patch staging & discard dibangun di `crates/diff` dengan input melalui filter pipeline `gix` (`convert_to_git`) | `core` tetap bebas isi file; file CRLF di Windows (`core.autocrlf=true`) hanya memunculkan diff perubahan nyata sementara `new_blob` menjaga hash byte mentah | P1 |
| 2026-11-22 | Simpan catatan pre-push review & undo stack di satu DB SQLite (`rusqlite`, fitur `bundled`) di folder app data | Tidak mengotori `.git`, tidak butuh instalasi SQLite di Windows, dan undo stack bertahan lintas restart | P1 |
| 2026-11-22 | Kalibrasi default `DiffOptions::max_work` ke `10_000_000` dengan budget `criterion` via `cargo xtask bench-check` | Menjaga worst-case diff di bawah batas cancel 200 ms dan menggagalkan CI otomatis saat regresi kompleksitas | P1 |
| 2026-11-23 | Tunda dogfood manual 2 minggu hingga setelah v0.3 (`P12`) & adopsi workflow per fase dengan `docs/phases/` | Fitur v0.2 & v0.3 tidak terblokir dogfood manual, bisa dikerjakan paralel di worktree, dan tiap sesi hanya membaca 1 file fase | P1 |
| 2026-11-23 | Cherry-pick dan revert hanya dimulai saat repo `Clean`, HEAD sama dengan saat diminta, dan tidak ada perubahan pada file tracked (staged/unstaged); hasil bersih memakai undo `Reversal::Refs`, konflik menjatuhkan undo point dan memakai alur konflik P1 | Harness menemukan `git revert --abort` menimpa edit unstaged yang sudah ada saat pick dimulai (data hilang); undo ref+index konsisten dengan commit (law 8) | P2 |
| 2026-11-23 | Tag annotated disimpan apa adanya di `RefsSnapshot.refs` (id tag object), commit targetnya di `peeled_tags`; push/hapus tag remote memakai `Irreversible::Push` | Guard expected-state & undo harus membandingkan nilai ref asli agar delete annotated bisa di-undo persis; badge pakai target commit; tanpa mengubah format undo tersimpan | P3 |
| 2026-11-23 | Blame & file history dibaca lewat `git blame --porcelain` dan `git log --follow --name-only` (read-only, `GIT_OPTIONAL_LOCKS=0`) di `crates/shell/src/blame.rs`, bukan `gix` | `gix` belum punya blame yang mengikuti rename maupun log `--follow`; keluaran git sendiri adalah oracle yang tepat. Dijalankan di thread terpisah dan child di-kill saat cancel, jadi pindah file tidak memblokir UI | P5 |
| 2026-11-23 | Jalankan editor interactive rebase melalui executable native `invoke-rebase-editor` di direktori app, dengan basename polos di `GIT_SEQUENCE_EDITOR`, direktori di `PATH` child Git, dan todo di file sementara | Git menjalankan basename secara langsung pada Linux dan Git for Windows. Path instalasi dengan spasi/backslash tetap menjadi data native. File sementara menghindari batas panjang environment pada Windows, dan sentinel internal Git `:` menerima pesan squash/continue tanpa proses editor | P4a |
| 2026-11-23 | Search memakai filter eksplisit `SearchField`, walk gix breadth-first dari tips graph, dan path literal terhadap parent pertama | Walk menghasilkan halaman tanpa penelusuran topologis awal. Perbandingan path konsisten dengan commit detail dan hanya membutuhkan entri yang dicari | P6 |
| 2026-11-23 | Reflog (`HEAD` & branch lokal) dibaca read-only lewat `gix` (`log_iter().all()` forward-lalu-reverse) di `crates/shell/src/reflog.rs`; reset pemulihan hanya menyediakan `ResetMode::Soft` dan `ResetMode::Mixed` (bukan `--hard`) dengan `Reversal::Refs` | Membaca forward-lalu-reverse menghindari truncation buffer jendela tetap milik reverse iterator `gix`; membatasi reset ke `Soft`/`Mixed` menjaga file worktree tidak pernah tertimpa dan menjamin undo persis (Law 8 & 9) tanpa mengubah format `u1` / skema SQLite `P1` (checkout file commit lama tetap tersedia lewat create-branch + switch yang undoable) | P7 |
| 2026-11-23 | Parse file blame off-thread dengan konteks sintaks satu file dan bentuk style untuk baris virtualized yang diminta | Capture yang melintasi newline tetap tepat, dan pekerjaan rendering dibatasi ke baris yang diminta GPUI | P5 |
| 2026-11-23 | Batasi hasil commit search di UI hingga 500 dan hentikan scan saat batas tercapai | Satu query luas tidak menahan metadata untuk seluruh history, dan user dapat mempersempit filter | P6 |
| 2026-11-23 | Ikat konfirmasi reset reflog ke HEAD dan index yang terlihat saat form dibuka | Konfirmasi yang sudah terbuka tidak bisa dikirim setelah ref aktif atau index berubah, sebelum guard shell memeriksa operasi yang diberikan core | P7 |
| 2026-11-24 | Pilihan binary git adalah fungsi murni `git_discovery::resolve` (probe versi dan cek file diinjeksi): system git ≥ 2.40 selalu menang, MinGit di `<dir app>\mingit\cmd\git.exe` hanya fallback, dan `SetupError::FallbackFailed` bila keduanya tidak bisa dipakai | Logika prioritas bisa diuji tanpa git sungguhan dan tanpa jaringan; sistem tidak pernah tergeser oleh bundel | P11 |
| 2026-11-24 | MinGit dipin ke 2.56.1 64-bit (`v2.56.1.windows.1`, SHA-256 `4a92850b…dfefdafd`) dan diunduh oleh `cargo xtask package-windows` dengan hash diverifikasi lewat PowerShell `Get-FileHash`, unzip lewat `System32\tar.exe`, tanpa crate baru | Hash dicocokkan dengan release notes resmi dan dihitung ulang dari zip; crate hashing di luar tabel PRD tidak diperlukan | P11 |
| 2026-11-24 | Forge (akun, token, klien API) hidup sebagai modul `crates/shell/src/forge/` dengan bagian murni (akun, pencocokan host, mesin sign-in, filter repo) di `crates/core/src/forge.rs`; bukan crate `crates/forge` terpisah | Aturan arsitektur: core murni tanpa IO, IO hanya di shell. Crate baru hanya menambah graf dependensi tanpa batas yang berguna, dan tes `forge_auth` tetap bisa dijalankan dengan `-p shell` | P8 |
| 2026-11-24 | Token forge hanya disimpan lewat trait `TokenStore` (`keyring` di app, memori di tes); daftar akun (jenis, host, username) di file teks `forge-accounts.txt` tanpa token; `Secret` menyembunyikan nilai di `Debug`; pesan error tidak pernah memuat body, URL, atau teks pustaka | Law kredensial PRD: tidak ada token di config teks, log, atau pesan error. Tes memindai folder data untuk memastikan tidak ada token tertulis | P8 |
| 2026-11-24 | HTTP forge lewat satu pengirim `reqwest::blocking` (native-tls) yang menolak URL non-https kecuali loopback, tidak mengikuti redirect, membatasi body 8 MiB, dan hanya mengikuti `Link: rel=next` yang satu origin | Token tidak boleh ikut redirect atau `Link` jahat ke server lain, dan tidak boleh lewat jaringan tanpa enkripsi | P8 |
| 2026-11-24 | Tanpa `serde_json`, `sha2`, `rand`: JSON reader kecil, SHA-256, base64url, dan PKCE ditulis sendiri (diuji vektor RFC/FIPS + proptest); acak dari `BCryptGenRandom` (Windows) atau `/dev/urandom` | Aturan: tidak menambah crate di luar tabel build-vs-library PRD tanpa bertanya; permukaan yang dibutuhkan kecil dan mudah diverifikasi | P8 |
| 2026-11-24 | GitHub: OAuth device flow tanpa client secret, scope `repo`; GitLab.com: OAuth PKCE (S256) lewat listener loopback `127.0.0.1:47821`, scope `read_api`; self-hosted GitLab dan fallback semuanya PAT + URL instance; client id OAuth masih kosong (spec gap) sehingga PAT jalan lebih dulu | PRD tabel forge. GitLab menuntut redirect URI persis sehingga port tetap; scope minimal untuk daftar repo, dinaikkan di P9 bila perlu | P8 |
| 2026-11-24 | Akun dicocokkan ke remote lewat hostname saja (tanpa port/skema), `ssh.github.com` dan `altssh.gitlab.com` dianggap host forge yang sama; beberapa akun pada satu host meminta pilihan sampai satu ditandai sebagai pilihan host itu | PRD: banyak akun per forge, dipilih per remote lewat host; ssh dan https ke host yang sama harus memakai akun yang sama | P8 |
| 2026-11-25 | Setiap perubahan daftar akun forge (sign-in, disconnect, preferensi, undo, tulis token hasil refresh) memegang kunci OS pada file `forge-accounts.lock` (`std::fs::File::lock`, tanpa crate baru) selama seluruh siklus baca-cek-tulis daftar dan keychain; file sementara unik per tulisan; UI hanya membaca snapshot di memori | Dua proses (atau dua jendela) bisa membaca keychain kosong yang sama lalu saling menghapus atau menimpa credential; kunci file menyerialkan siklus itu lintas proses, guard isi file tetap menolak penulis yang tidak memakai kunci, dan render tidak pernah menunggu IO keychain/disk | P8 |
| 2026-11-24 | Gunakan perintah Git dengan path literal untuk aksi seluruh file dan patch untuk seleksi hunk atau baris | Git menangani binary, encoding, symlink, dan mode. Stage dan unstage menyiapkan index privat serta memasangnya selama `index.lock` dipegang | P1b |
| 2026-11-24 | Simpan byte dan timestamp index, tree staged, serta shared index yang dirujuk dalam satu tree undo | Byte index menyimpan flag intent-to-add. Timestamp mempertahankan cara Git memeriksa stat yang berimpit. Tree staged melindungi objek dari pruning Git dan shared index memungkinkan undo setelah base split index kedaluwarsa | P1b |
| 2026-11-24 | Siapkan checkout dan snapshot sesudah discard sebelum worktree diubah | Checkout Git menerapkan filter dan CRLF. Konfirmasi mengikat index, byte, dan mode Git. File intent-to-add diperlakukan seperti file untracked untuk discard worktree, sambil mempertahankan entri index | P1b |
| 2026-11-24 | Di Windows hanya reparse point name-surrogate (symlink, junction) dianggap link; checkout discard memakai `core.longpaths=true`, dan file atau folder di jalur yang nama on-disk-nya beda huruf ditolak | Placeholder OneDrive/dedup adalah file atau folder biasa. Penolakan beda huruf mencegah file lain di-hash atau ditimpa | P1b |
| 2026-11-24 | Scratch discard dan undo-nya berada di bawah git dir bila satu volume dengan worktree; jika tidak, di root worktree | Status dan watcher tidak melihat git dir, dan rename dalam satu volume tetap atomik. Root worktree hanya fallback untuk git dir di volume lain (`--separate-git-dir`, linked worktree di drive lain) | P1b |
| 2026-11-25 | Install Git-produced or saved index bytes directly through Git's lock-and-rename protocol | Git CLI still computes index changes on a private index. Publishing it under the same held `index.lock` closes the expected-state race. Exact snapshot installation also preserves flags, timestamps, split-index references, and an originally absent index for Law 8 | P1b |
| 2026-11-25 | Keep scratch in ordinary repository metadata or outside the worktree, and require a same-volume location for discard/undo | Replaces the root fallback above. Separate Git directories inside a worktree can be staged. Atomic, no-replace rename protects concurrent editor saves and leaves a recoverable scratch copy if rollback cannot restore a moved entry | P1b |
| 2026-11-25 | Refuse Windows junction leaves for staging and discard. Materialize native symlink checkouts in Rust | Git can traverse junctions during add, and discard snapshots represent symlinks but cannot recreate junctions faithfully. Emulated checkout bypasses Git for Windows target probing before bounded link creation | P1b |
